## 0. 这次重审改变了什么

负责人 2026-10-21 的修正：

- YUVI_NEXT 是一个新的个体，不是 Alice 或旧 Yuvi 的延续。

```
WP-A 档案存取增量化 ──┬──▶ WP-B 统一组装与呈现记录 ──┬──▶ WP-E 回忆与浮现 ──▶ WP-F 重整与激活

                                                                 │
                                         WP-G 语义向量（仅当 D3 批准且 H6 需要）
```

- **WP-A 必须最先做：**
  - 不消除整表解码，任何规模实验都不可信；
  - 不参数化场景/分支，后面每个工作包都会在硬编码上叠加。
- **WP-B 在 WP-E 之前：** 没有呈现记录，回忆与浮现是否到达模型、是否被用到，都无法测量，会重演 V1 的“生成了却没有消费者”。
- **WP-C 在 WP-E 之前：** `recall` 和浮现都需要能排序的检索。
- **WP-D 在 WP-E 的默认开启之前：** 机制可以先实现、默认关闭；是否默认开启，由评测台的对照结果决定。
- **WP-F 在 WP-E 之后：** 重整需要先有检索来选出相关的旧文字；激活需要先有回忆与浮现的历史。

## 3. 工作包

工作量是 Sol 的工作日估计，含测试；P1–P4 的实际交付约为每个 P 1–2 天，下列估计已按此校准。每个 WP 都是一个对 `main` 的 PR，验收标准在 P 文件中事先写定。

### WP-A　档案存取增量化（必须先做的基础）

- **交付：**
  - 回合、整理、查档的路径不再读取并解码整张事件表。改为 SQL 查询或增量维护的状态；结果与现在逐条一致。
  - `scene`、`branch` 从常量改为参数，仍只启用 `web` 与 `dev:v2-dev`。
- **验收：**
  - P1–P4 全部回归不变（含 D1–D21 的独立脚本）；
  - 1M 事件合成档案、假模型下，普通回合的程序开销 p95 < 100 ms（现为 100k 事件 3–5 s）；查档回合的开销如实记录，由 WP-C 改进；
  - 档案 schema 不变。
- **不做：** 新事件种类；新场景。
- **估计：** 1–2 天。**风险：** 低。

### WP-B　统一组装与呈现记录（基础）

- **交付：**
  - 对话、整理两类请求由同一个组装处生成；
  - 每次请求前写一条 `control/presented`（在 TERMS 登记），记录前景、窗口、各部分字数与总字数、组装规则版本；
  - 提供一个只读的维护命令，从档案统计每段文字被呈现的次数与时间（消费覆盖率）。
- **验收：**
  - 请求内容与现在逐字节一致（只是多记录一条事件）；
  - 记录与实际请求一致（假模型服务端比对）；
  - 每回合额外写入的字节数与时延写进 PR，作为实测（H8）；
  - 呈现记录不进入任何模型上下文。
- **估计：** 1–2 天。**风险：** 低。

### WP-C　派生索引与查档升级（基础）

- **交付：**
  - 数据目录中独立的 `index.sqlite`：
    - 对话事件与它的文字的文本索引（中文可用，方案在 P 文件前由一个小探针确定：FTS5 trigram + 单字/二元组补充，或自建二元组倒排）；
    - 时间、作者、场景；
    - 水位 `through_seq` 与规则版本。
  - 版本不符或校验失败时整体重建。提供 `verify` / `rebuild` 维护命令。
  - `check` 改走索引：先排序再截断，结果按时间呈现；匹配总数如实；候选受限时明说。参数与返回格式向后兼容。
  - 快照与恢复不依赖索引：恢复后自动重建。
- **验收：**
  - 冻结一套中文/英文/标识/两字词/长文尾部的查询集，每条有标准答案（借用 V1 R5 暴露过的失败形态：高频旧事实、长中文尾部、两字查询、换说法）；
  - 记录命中率，**失败如实保留**；
  - 人为损坏索引能检出并重建；
  - 1M 事件下重建时间与查询 p95 作为实测记录；
  - P4 的 `check` 验收项（D 系列）全部仍通过。
- **估计：** 2–4 天。**风险：** 中（中文分词方案）。

### WP-D　评测台：合成的长期生活（研究旁路，与 B/C 并行）

- **交付（研究代码，放在 `research/`，不进入产品路径）：**
  - **生活脚本生成器：** 若干周到若干月的合成生活，包含：反复出现的话题、会变化的事实（搬家、换工作、改名字）、更正、多次提到的人、长时间的空白、无关的日常。每个可检验的点带标准答案。
  - **驱动器：** 通过真实服务入口（HTTP），配合可加速的时钟，按脚本中的时间间隔发送消息，让整理（以后还有重整）**在每段空闲中真实地发生**，而不是一次性灌入。
  - **指标：**
    - 跨期召回：隔天、隔周、隔月问起时，它能否说出；
    - 更正之后的说法；
    - 话题重复率；
    - 文字的消费覆盖率（来自 WP-B）；
    - 每回合成本与时延。
- **两种运行：**
  - **假模型：** 检验机制，进入 CI，不花钱；
  - **真实模型：** 检验假设 H1–H8。每次运行前由负责人批准预算；结果冻结，保留全部失败。
- **验收：**
  - 假模型下一次 8 周合成生活可以在 CI 时间内跑完；
  - 指标可以复算；
  - 同一种子可以复现同一生活脚本。
- **估计：** 3–4 天。**风险：** 中（指标的效度，需要负责人审阅脚本样例）。

### WP-E　回忆与浮现（记忆过程第一部分）

- **交付：**
  - `recall` 工具（它的文字，按查询与时间），入档 `act/recalled`；
  - 线索浮现（可配置，默认关闭），进入呈现记录；
  - 组装中浮现部分的位置与上限；
  - 只返回当前场景可见的文字（[03 §9](03-architecture.md) 第 5 条的最小实现：目前只有一个场景，但过滤逻辑在此时写定）。
- **验收：**
  - 假模型下机制正确（调用入档、返回与呈现记录一致、上限）；
  - 评测台对照（真实模型，需批准）：浮现开/关、新近对照，记录 H1、H2、H7 的结果；
  - 是否默认开启浮现，由负责人依结果决定。
- **估计：** 2–3 天（不含真实模型评测的等待）。**风险：** 中（真实模型是否会使用 `recall`）。

### WP-F　重整与激活（记忆过程第二部分；研究性最强）

- **交付：**
  - 空闲时的重整：选材规则有版本；产物为 `inner/wrote`；它可选地表示哪些旧文字已被包含，该选择入档（在 TERMS 登记）；
  - 前景按激活选入（可配置；新近规则为对照）；
  - 前景只在整理/重整后重算。
- **验收：**
  - 假模型下机制正确；
  - 评测台上 8 周以上合成生活的对照（H3、H4），包括自我强化与漂移的指标；
  - 默认行为由结果决定。
- **估计：** 3–5 天。**风险：** 高（这是研究问题，可能得到“无增益”的结论；那也是有效结果）。

### WP-G　语义向量（条件性）

- **前提：** 负责人批准 [05 D3](05-decisions.md)，且 WP-C/WP-E 的评测显示换说法、跨语言漏检显著（H6）。
- **交付：**
  - 嵌入接口（本地或 API，按 D3）；
  - 只对它的文字建向量，按模型空间分代存在 `index.sqlite`；
  - 与文本通道融合；
  - 评测台上的有/无对照。
- **估计：** 2–3 天。**风险：** 中（成本、模型空间升级）。

## 4. 历史模拟与动力学实验：什么时候、怎样做

- **区分两件事：**
  - 一次性把很长的历史灌进去（导入、回放），只检验“存取能不能找到”。它**不能**说明记忆在经历中怎样演化，因为整理、重整、遗忘都需要时间间隔与反复使用。
  - 长期记忆的动力学必须在**按时间展开的生活**中检验：每段空闲都真实地发生整理，每次被问起都真实地留下回忆的痕迹。
- **时间：**
  - 合成生活（WP-D）从基础阶段就开始做，先用假模型；真实模型的小规模运行从 WP-E 开始。
  - **ChatGPT 历史作为原生经历**保留为研究工具，但不排期。
    - 最早在 WP-F 之后、作为动力学的压力测试，在 `fork:` 分支中按真实间隔重放；
    - 数据由负责人提供并批准；
    - 结果不作为长期记忆成功的证据。
- **V1 历史：** 不导入。V1 的研究资产以文档和教训的形式进入（[02](02-inheritance.md)）。

## 6. 分类、成本与风险

| 类别 | 工作包 | 合计 |
| --- | --- | --- |
| **必须先做的基础** | WP-A、WP-B、WP-C | 约 4–8 天 |
| **并行的研究** | WP-D；潜在组织离线研究（另定） | 约 3–4 天 + 真实模型预算 |
| **记忆过程** | WP-E、WP-F | 约 5–8 天 + 评测周期 |
| **条件性** | WP-G | 约 2–3 天 |
| **暂缓** | 主动生活、QQ、身体、`main` 生活、ChatGPT 历史压力测试 | — |

**真实模型成本（推断）：**

- V1 R5 的实测（200 次调用约 $0.008）不能直接套用：那些请求的上下文很短，而 V2 每次请求带着前景文字与 200 个事件的原文窗口。
- 一次 8 周合成生活约 1,000–2,000 次请求；按每次 2–4 万输入 token 估算，约 2–8 千万输入 token。按常见低价模型的报价，并考虑前缀缓存，量级约为每次运行数美元到十余美元。这是推断，以实际报价与用量记录为准。
- 每次运行前单独报批，并设调用次数与估算费用的上限（V1 的做法）。

**主要风险：**

1. **评测台的效度。** 合成生活可能过于规整，使机制看起来有效。对策：负责人审阅脚本样例；保留真实使用作为最终检验；冻结评测集，不事后调整。
2. **动力学的自我强化与漂移。** 对策：重复率与覆盖率是必测指标；每个机制可开关、可消融。
3. **重演 V1 的“基础先行而记忆无用途”。** 对策：基础只有三个、各 1–4 天，并且每个都直接服务于 WP-E/WP-F 的测量；WP-B 先让“是否到达模型”可见。
4. **研究结论可能是“无增益”。** 对策：这是有效结论；对应机制不进入默认行为，P4 的规则继续作为基线。
