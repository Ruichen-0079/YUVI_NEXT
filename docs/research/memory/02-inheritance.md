# 02　V1 → V2 继承分析

> 2026-10-21，Claude。依据 [01](01-v1-review.md) 的调查；通用技术的具体选型见 [06](06-selection.md)。每项能力给出四种处理之一：
>
> - **保留**：V2 已有等价物，或思想直接沿用；
> - **重实现**：需要这个能力，用 V2 的结构和词汇重新做；V1 中已验证的算法与代码可以参考或移植，注明来源；
> - **替换**：需要解决同一个问题，但换一种做法；
> - **放弃**：问题本身不属于 V2，或做法与研究宗旨冲突。

## 1. 逐项处理

### 1.1 来源与边界（程序拥有的部分）

| V1 能力 | 处理 | V2 中的形态与理由 |
| --- | --- | --- |
| Journal（不可变事件 + 正文 + 来源去重） | **保留** | V2 档案已是只追加事件表（P1–P3）；字段更少，够用 |
| 意图 → 尝试 → 结果，UNKNOWN 不重做 | **保留** | 不变量 5；P1 的 `reply_attempt`/`control/error` |
| 用户原话入口同事务入档，与回复成败无关 | **保留** | P1 的 `heard` 先于生成入档 |
| 逐字引文约束（模型输出引用原文必须是唯一连续子串） | **重实现，限定用途** | 只用在边界：对外陈述归属、身份与权限依据、`check` 结果的逐字呈现。**不用于它自己的记忆**（不变量 3） |
| 来源谱系（MemoryLineageV1、episode-source-evidence） | **替换** | 记录可核验的关系即可：一段文字由哪些档案事件形成（`meta.material`，P4 已有），形成时它面前有什么（新增“上下文清单”，[03 §3.2](03-architecture.md)） |
| Host 授权、知识快照与权限分离 | **以后重实现** | 多人场景（QQ）时需要。保留一条教训：知识变旧 ≠ 权限撤销 |
| 观察（看图报告）与执行终态同事务、限期、可擦除 | **以后重实现** | C5 `look` 时需要；教训：报告与执行结果在同一提交边界 |
| 冷恢复、旧恢复点在新写入后拒绝复用 | **保留** | P3 快照/校验/恢复；派生索引不进入恢复的正确性前提（可重建） |
| 进程所有权、单写者 | **保留** | P3 单实例锁 |

### 1.2 存取（可重建的部分）

| V1 能力 | 处理 | V2 中的形态与理由 |
| --- | --- | --- |
| 索引 outbox、代际、水位、VERIFY/REBUILD/ADVANCE | **重实现** | 独立的派生索引文件，按档案 `seq` 记水位；损坏可检出、可整体重建；不进入档案数据库（[03 §6](03-architecture.md)） |
| 词项倒排（汉字单字 + 二元组，有界 posting） | **重实现，倒排交给 FTS5** | 继承 V1 的切分方式（汉字单字 + 二元组），倒排、排序、合并与删除用 Node 内置 SQLite 的 FTS5，不自写倒排（[06 §2](06-selection.md)）。保留教训：先排序再截断；候选受限要明说 |
| 向量通道（pgvector HNSW，Qwen3-Embedding-0.6B 512 维） | **按需引入** | 跨语言、换说法时需要。路线见 [06 §3](06-selection.md)：本地 llama.cpp/Ollama 运行同一模型，进程内暴力余弦。保留教训：向量属于某个“模型空间”，换嵌入模型就要整体重建 |
| 混合融合（RRF） | **重实现，晚于词项** | V1 原混合 3/10 劣于单一词项 10/10；融合本身需要评测 |
| 组合检索（程序把问题拆成需求） | **替换** | 让它自己在工具循环中多次查询；不建程序侧的查询规划层 |
| 查询扩展、证据支持判断（独立模型调用） | **放弃** | 都是程序侧的语义中间层；回答时由它自己判断证据够不够 |
| 检索运行记录（实际查询、命中、状态） | **重实现** | 已部分存在：`act/checked` 记录参数与返回序号；扩展为所有呈现给模型的记忆都可追溯 |
| PostgreSQL | **不采用（目前）** | 单实例、单个体的规模在 SQLite 能力内（V2 蓝图附录 E：1M 事件、444 MB 的文件复制约 0.2 s）。V2 目前在 100k 事件下每回合 3–5 s 的程序开销，来自每回合读取并解码整张事件表（P4 验收实测），不是 SQLite 的上限。到多进程写或 10M 级时再评估 |
| Mem0 | **放弃** | V1 已证明它不能承担长期记忆 |

### 1.3 记忆本身（它自己的部分）

| V1 能力 | 处理 | V2 中的形态与理由 |
| --- | --- | --- |
| `memories` 表的类型/层级/重要性/保留期 | **放弃** | 程序语义标注 |
| 关键词情绪标签（CurrentAffect） | **放弃** | 程序语义标注 |
| 时间规范化（把“今早”改写成日期） | **放弃** | 改写原文；V2 用带日期的本地时间呈现（P4） |
| R5 命题权威（当前知识投影 + 关系重评） | **替换** | 不建第三人称事实库。它写下的文字 + 可核验的形成关系 + 由它自己完成的重整（[03](03-architecture.md)）。保留思想：**历史只追加，“当前的样子”是可重建的投影** |
| supersedes / conflicts / supports | **替换** | 不由程序校验语义关系；由它在重整时自己写出新的理解，程序只记录“新文字由哪些旧文字形成” |
| L0 直接上下文 | **保留** | P4 原文窗口 |
| L1 近期情节（30 分钟切段） | **放弃** | 原文窗口与整理已覆盖 |
| Dream 整合 | **替换** | 重整（[03 §4.4](03-architecture.md)）：先定义消费者与测量，再实现 |
| 联想闯入（main 中运行，未评估） | **重实现为研究机制** | 线索触发的浮现（[03 §4.3](03-architecture.md)），可开关、可消融 |
| Profile / People model / P8 关系 | **放弃** | 对人的理解就是它写下的、与这个人有关的经历；“与谁有关”由可核验的作者关系给出，不由程序解释 |
| 前瞻连续性（承诺/期待/意图） | **暂不做** | 属于主动生活（原 C3），不作为记忆结构的字段 |
| 测量整合（切段 → 封闭标签 → 积分） | **保留其方法，不实现其结构** | “任何持久变量先有测量定义”作为研究纪律；封闭标签与心理标量不进入产品 |
| 持久内部状态的六条路线 | **保留为研究输入** | 潜在组织研究（原 C7）的起点 |

## 2. 怎样摆脱过时的外部库和拼接层，又不丢掉成熟的基础

V1 的复杂性有两个来源，处理方式不同：

1. **外部库与其适配层**（Mem0 sidecar、PG 扩展的打包，以及为它们写的契约层）。问题不在“用了外部库”，而在于用了一个接管记忆语义的库，并为它搭了多层适配。V2 按 AGENTS“依赖与架构选型”选择职责单一、边界稳定的成熟组件，放在可重建的派生层，换掉它不伤害任何资产（选型见 [06](06-selection.md)）。
2. **为保证语义正确而建的结构**（当前知识投影、关系重评、查询规划、支持判断、Profile、P8）。V2 不继承这些结构，因为它们要解决的问题（“程序保证它记得的是对的”）V2 已经决定不由程序解决（决定（a））。

真正要继承的是 V1 在**做这些结构时学到的存取知识**：先排序后截断、通道独立失败、候选受限要说明、模型空间要版本化、派生层要有水位和校验、逐字引文能抓住模型的抄写错误。这些知识主要以“验收标准”和“设计约束”的形式进入 V2 的工作包；V1 中可以直接复用的算法与代码片段，可以移植并注明来源。

## 3. 一页结论

| 继承 | 内容 |
| --- | --- |
| 原样保留 | 只追加档案；UNKNOWN；原话先入档；快照与恢复；单写者 |
| 重新实现 | 派生索引层（水位、校验、重建）；中文可用的词项检索；可追溯的呈现记录；评测台；（以后）多人授权与观察保留 |
| 按需引入 | 语义向量与嵌入模型（本地运行 Qwen3-Embedding-0.6B） |
| 替换 | 第三人称事实权威 → 它自己的文字与重整；程序侧查询规划 → 它自己的工具循环；Dream → 有消费者的重整；Profile/P8 → 由作者关系连接的经历 |
| 放弃 | Mem0；类型/层级/重要性/保留期/情绪标签；时间改写；查询扩展与支持判断的独立层；L1 |
