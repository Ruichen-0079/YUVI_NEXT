# 05　决定：已采用的立场与留给负责人的事项

> 2026-10-21 初稿列出 D1–D5 五项待批事项。同日负责人基本认可 PR #13 的架构与路线，并要求把它们收敛为原则性立场。本文记录收敛后的结果。
>
> 分工：
>
> - **一般工程选型：** 由 Claude 提出有依据的方案（[06](06-selection.md)），Sol 在实施中落地；
> - **负责人：** 只决定不可逆的数据边界、隐私授权与重大研究目标变化。

## 1. 已采用（原则上）

| 原编号 | 立场 | 留有的余地 |
| --- | --- | --- |
| D1 | 采用四类划分：可信来源与边界、可重建的存取结构、它自己的记忆资产、程序的语义判断（默认不存在）。“语义计算”进入存取层的五条条件（[03 §1.1](03-architecture.md)）作为判断标准 | 细化条文在第一个用到它们的工作包的 PR 中写入 TERMS/AGENTS（[03 §9](03-architecture.md)） |
| D2 | 它自己写下的自由文字是**当前**主要的记忆载体；不建第三人称事实库、当前知识投影、Profile 或人物模型 | 不排斥以后的其他表示；引入时说明归属（四类中的哪一类）并与现有载体比较 |
| D3 | 语义向量**按实际需要**引入；路线是本地嵌入进程（[06 §3](06-selection.md)） | 引入条件：WP-C/WP-E 的评测显示换说法、跨语言的漏检显著 |
| D4 | 按访问历史的激活作为**可开关、可比较**的研究机制；ACT-R 基础激活为初始模型，P4 的新近规则始终保留为对照 | 其他动力学模型（如 FSRS 类）可以作为对照加入；多场景可见范围的推论（[03 §9](03-architecture.md) 第 5 条）随 WP-E 写定 |
| D5 | 总体路线采用（[ROADMAP](../../ROADMAP.md)）：记忆过程先于主动生活、QQ、身体；Alice 切换与 V1 导入删除，PR #12 保留不合并 | 技术细节按选型调研修正，由 P 文件确定 |

## 2. 留给负责人的事项（都不阻塞 WP-A～WP-C）

| 事项 | 何时需要决定 | 为什么属于负责人 |
| --- | --- | --- |
| 私人文字能否送往外部服务做嵌入 | 只有当本地嵌入不够用、考虑外部 API 时 | 隐私边界 |
| 删改事件与它的记忆：由被删内容形成的文字如何处理（[03 §4.7](03-architecture.md)） | 第一个实现删改事件的工作包之前 | 隐私与“它自己的记忆”之间的取舍，不可逆 |

| 真实模型实验的预算 | 每次运行前（从 WP-E 开始） | 费用 |
| ChatGPT 历史作为原生经历的压力测试 | 最早在 WP-F 之后 | 私人数据与研究目标 |
