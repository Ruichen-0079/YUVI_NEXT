# 05　需要负责人决定的事

> 2026-10-21，Claude。只列研究方向、系统边界和不可逆的工程选择。每项给出建议与理由；不选建议项也有可行的路线，代价写在后面。局部技术方案留给 P 文件和 Sol。

## D1　采用“四类东西”的划分，以及对原则的细化

- **内容：**
  - 采用 [03 §1](03-architecture.md) 的四类：可信来源与边界、可重建的存取结构、它自己的记忆资产、程序的语义判断（默认不存在）；
  - 采用 §1.1 的五条，作为“语义计算”可以进入存取层的条件；
  - 批准 [03 §9](03-architecture.md) 的第 1–4 条细化，在对应 P 的 PR 中写进 TERMS / AGENTS。第 5 条见 D4。
- **建议：采用。**
- **理由：**
  - 不细化，语义索引、浮现、激活都会被逐个当作“程序判断意义”来争论；
  - 不设界线，V1 式的打分会以“检索需要”的名义回来；
  - 五条是两者之间的分界。
- **不采用的代价：** 存取只能停留在子串与时间（P4 现状），WP-E/WP-F 无法进行。

## D2　记忆的主要载体：它自己写下的文字，而不是事实库

- **内容：**
  - 记忆资产是它写下的文字（整理与重整的产物）及它自己做出的组织选择；
  - 对人的理解由“与谁的经历有关”这一作者关系连接；
  - **不建立**第三人称命题库、当前知识投影、Profile 或人物模型。
- **建议：采用。**
- **理由：**
  - V1 的主要失败是对象错误：记的是用户，不是它自己的生活；
  - 程序固化当前状态，带来了 R5 的结构性写入失败；
  - 决定（a）已经确定更正由它自己采纳。
- **可推翻的条件：** 评测台上 H1 显示，它自己的文字在负责人在意的事实上明显劣于离线的事实摘录对照，且重整（H3）不能弥补。届时再讨论是否需要一个由它自己维护、而不是程序维护的“笔记本”式结构。
- **不采用的代价：** 回到 V1 R5 的路线，需要重建命题、关系与投影，并重新面对其已知的失败。

## D3　是否引入语义向量，以及嵌入模型放在哪里

- **内容：** 是否允许一个外部嵌入模型进入系统；如果允许，选本地（如 Qwen3-Embedding-0.6B，经 llama.cpp/Ollama 运行）还是 API。
- **建议：**
  - 先不引入；WP-C/WP-E 只用文本索引；
  - 由评测台测量换说法、跨语言的漏检率（H6）；
  - 漏检显著时再做 WP-G，届时优先**本地**模型：私人内容不出本机，没有按次费用，模型空间由我们自己固定。
- **理由：**
  - V1 的实测里，中文标识与已知事实上文本通道优于向量（10/10 对 6/10）；
  - 向量的价值在于换说法和跨语言，这需要先测量；
  - 引入后，每次换嵌入模型都要整体重建，并多一个运行依赖。
- **需要你决定的是边界：** 将来是否允许私人文字被送到外部嵌入 API。

## D4　程序定义的存取动力学

- **内容：** 是否允许程序按可核验的访问历史（形成、被想起、被浮现的时间）计算激活值，用来排列前景与浮现的候选（[03 §4.4](03-architecture.md)）。
- **建议：** 允许，作为显式的研究机制：
  - 有版本，可开关；
  - 默认行为由评测台决定；
  - P4 的新近规则始终保留为对照。
- **理由：**
  - V1 的记忆动力学从未运行，原因之一是没有一个被允许存在的落点；
  - 这里的规则只看访问的时间，不看内容，满足 D1 的五条；
  - 但它确实是“程序决定什么更容易被想起”，属于研究宗旨的边界，因此需要你明确同意。
- **一并决定（03 §9 第 5 条）：** 一段文字的可见范围取其形成材料中最严格的那个；浮现与 `recall` 只返回当前听众可见的文字。建议采用。目前只有一个场景，影响在多人场景时才出现，但规则应在 WP-E 中写定。
