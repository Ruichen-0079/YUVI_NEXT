# 03　YUVI_NEXT 候选记忆架构

> 2026-10-21，Claude。负责人已原则上采用本架构（见 [05](05-decisions.md)）。它仍不是规格：实现以 P 文件为准。标为“假设”的部分必须先经评测（[ROADMAP](../../ROADMAP.md) WP-D 及各机制的工作包）检验，不能直接作为默认行为上线。通用技术选型见 [06](06-selection.md)。

## 0. 要解决的问题

P1–P4 交付了一个忠实的档案、一次“离开视野前先经过它自己”的整理，以及逐字查档。它还不是一个记忆过程：

- **它写下的文字只按新近选入。** 预算（默认 16,000 字）之外的旧文字只能用子串 `check` 找回，而它必须先知道要找的原词。
- **没有任何东西会因为被想起而更容易想起，也没有东西会退到背景。** 旧文字不会被重新理解，只会被新文字挤出预算。
- **看不到记忆是否到达了模型。** 档案记录了它写了什么，没有记录每次请求实际放进了什么。V1 的“生成了却没有消费者”在 V2 中同样无法发现。
- **规模。** 每回合读取并解码整张事件表：100k 事件时普通回合 3–5 s、查档回合 5.8 s 的程序开销（P4 验收实测，假模型）。
- **只有一个场景、一个分支是硬编码的。** `scene='web'`、`branch='dev:v2-dev'` 写死在 `src/context.ts` 与 `src/archive.ts` 中。

目标：**一个统一的个体记忆过程**。经历形成记忆，记忆被存取、被重新激活、被它自己重新组织，并且每一次参与生成都可以事后看到。V1 成熟的存取工程以可重建的派生层进入，不进入它的记忆本身。

**不做：** 第三人称事实库；程序侧的语义标签、重要性、情绪；对外陈述的事实保证（仍按 N2：对别人陈述前先查档，是规范而不是机制）。

**第一代，不是终点。** 它自己写下的自由文字是当前的主要记忆载体，ACT-R 式激活是初始的研究机制。二者都不排斥以后加入其他记忆表示（例如模型生成的其他形式、潜在状态）或其他动力学模型；加入时按 §1 的四类划分确定其归属，并与现有机制在评测中比较。

## 1. 四类东西

调查中反复出现的混乱，几乎都来自把下面四类东西混在一起。架构的第一条规则是把它们分开。

| | 是什么 | 谁写 | 可以错吗 | 能重建吗 | 换模型后 |
| --- | --- | --- | --- | --- | --- |
| **① 可信来源与边界** | 谁、何时、在哪、回复谁、对谁可见、发送尝试与结果、删除 | 程序 | 不可以；未知写 `unknown` | 不能，它就是历史 | 不变 |
| **② 可重建的存取结构** | 文本索引、时间/作者/场景索引、形成关系图、激活历史的汇总、（可选）语义向量 | 程序，从档案导出 | 可以有缺陷，但必须能检出 | **能**，随时可从档案整体重建 | 语义向量须按新模型空间重建；其余不变 |
| **③ 它自己的记忆资产** | 它写下的文字（整理与重整），它自己做出的组织选择（例如“这几条已被新写的包含”） | 它（模型调用），程序原样入档 | **可以**，不准确、会变形，都是它历史的一部分 | 不能，它们是档案中带版本的事件 | 文字原样延续 |
| **④ 程序的语义判断与控制** | “这句话是什么意思”“这条重要吗”“这是什么情绪” | — | — | — | — |

**④ 默认不存在。** 需要它时，在 P 文件中明确授权（TERMS §2）。

**① 与 ③ 的界线**由已确认的决定（a）给出：更正是 ③ 的材料，不是 ① 的事实；身份、权限、访问范围属于 ①（[ROADMAP §2.2](../../ROADMAP.md)）。

### 1.1 灰色地带：语义计算不等于语义判断

“不允许程序生成语义标签”不应被理解为“不允许语义索引、模型生成的表示或动态组织”。区分的标准不在于计算是否用到语义（全文检索的打分、向量相似度都用到），而在于**它的结果去了哪里**。

一项计算可以放在 ②，当且仅当它满足全部五条：

1. **只决定候选与呈现顺序。** 结果只用来决定“把什么放到它面前”，由它自己的过程去理解。
2. **不写成档案事件或记忆资产的属性。** 不出现 `importance=0.8`、`topic='work'` 之类的字段。
3. **不删除、不改写、不永久隐藏内容。** 没被选中的东西仍可通过 `recall` / `check` 找到。
4. **有版本、可重建。** 规则或模型空间变了，整体重建；旧版本的选择仍可从呈现记录（§3.2）复原。
5. **它选了什么被记录下来。** 每次请求实际呈现了哪些记忆，可以事后查到。

按这五条：

- 全文检索、向量相似度、按访问历史计算的激活值，**可以**作为存取机制。
- 按内容打分决定保留期、按关键词判断要不要删除、给文字贴主题，**不可以**。

动力学规则（例如“最近被想起的更容易浮现”）属于 ②。它们是研究假设，必须显式、可开关、可消融，并按 §8 测量。

## 2. 结构

```
                ┌──────────────── archive.sqlite（只追加；①与③） ────────────────┐
  经历 ───────▶ │ experience/heard  act/said  act/silent  control/error  …         │
                │ inner/wrote ← 整理 / 重整（它写下的文字；③）                      │
                │ act/checked  act/recalled ← 它主动查档 / 主动回忆                │
                │ control/presented ← 每次请求实际呈现了什么（清单）               │
                └───────────────┬───────────────────────────────▲───────────────────┘
                                │ 按 seq 增量导出                │ 原样入档
                ┌───────────────▼──────────── index.sqlite（②，可整体重建）──────┐
                │ 文本索引（档案原文 + 它的文字）  时间/作者/场景                  │
                │ 形成关系（文字 ← 原文；文字 ← 旧文字）  激活历史汇总            │
                │ （可选）语义向量：只对它的文字，按模型空间分代                    │
                └───────────────┬──────────────────────────────────────────────────┘
                                │ 候选与顺序
           ┌────────────────────▼────────────────────┐
           │ 呈现（唯一的组装处）                     │
           │ 人设 │ 前景记忆 │ 原文窗口 │ 浮现 │ 当前输入 │ ──▶ 模型 ──▶ 回复 / 沉默 / 工具
           └──────────────────────────────────────────┘                │
                ▲                                      check（档案原文）│ recall（它的文字）
                └──────────────────────────────────────────────────────┘
       空闲时：整理（原文 → 新文字）；重整（旧文字 → 新文字）
```

**统一与分开：**

- **统一的：**
  - 一个档案：经历、它的文字、它的存取行为、呈现记录都在同一条只追加的时间线上。
  - 一个写入机制：整理与重整都只产生 `inner/wrote`。
  - 一个组装处：所有进入模型的记忆都经过它，都被记录。
- **分开的：**
  - 派生索引放在独立文件，不进入档案数据库。档案的 schema 校验要求表结构完全一致（`src/schema.ts`），这本身就是一道隔离。
  - 档案原文（`check`）与它自己的文字（`recall`）是两个不同的工具，对应“查得到 ≠ 记得”。

## 3. 数据流

### 3.1 一次回合

1. `heard` 入档（P1）。
2. 必要时先整理（P4 的压力规则）。
3. **组装**（§5）：人设、前景记忆、原文窗口、浮现、当前输入；写一条 `control/presented`。
4. 模型生成：可调用 `check`（档案原文）、`recall`（它的文字）、`stay_silent`；每次调用入档。
5. 结局：`said` / `silent` / `error`（P1–P2）。
6. 回合结束后，索引按 `seq` 增量更新，不阻塞回复。

### 3.2 呈现记录（`control/presented`，新增，需登记）

每次模型请求之前写一条，`meta` 记录：

- 用途：对话 / 整理 / 重整；
- 前景记忆与浮现记忆的 `seq` 列表；
- 原文窗口的起止 `seq`；
- 各部分的字数与总字数；
- 组装规则的版本。

它只表示“程序把这些放进了请求”，**不表示它读了、注意到了或相信了**。

它解决三个问题：

1. **消费覆盖率可以测量：** 每段文字形成之后，是否曾被呈现、何时、多少次（V1 的 Profile/Dream 问题由此可以被发现）。
2. **激活历史有了可核验的来源：** 被呈现、被想起都是档案中的事实，不是程序的解释。
3. **研究可以复原任何一次生成的输入**，包括换模型、换组装规则前后的差异。

大小：每条约数百字节；每天 200 回合约 0.1 MB/天，可以接受。实际开销在 WP-B 中测量。

## 4. 生命周期

### 4.1 形成（已有：P4 整理）

- 保持 P4 的保证：对话事件离开原文窗口前，至少在一次整理中交给它读过；它写什么、写不写由它决定。
- 新增：整理请求同样写 `control/presented`。这样一段文字“形成时它面前有什么”（哪些旧文字、哪段原文）可以核验。

### 4.2 存取（新增：派生索引）

- **档案原文：** 对话事件与它的文字进入文本索引。`check` 改为走索引：
  - 先按相关度排序再截断，结果按时间呈现；
  - 匹配总数如实给出；候选受限时明说。
- **它的文字：** 另有 `recall` 的检索。
- **结构索引：**
  - 时间、作者、场景；
  - 形成关系：文字 ← 它读过的原文；文字 ← 重整时读过的旧文字；
  - 与人的关系：文字的材料中出现过谁。这是作者关系，不是语义判断。
- **中文：** SQLite FTS5 的 trigram 分词在 Node 内置 SQLite 中可用（本次在 Node v22.22.0 / SQLite 3.50.4 上实测；README 允许的最低版本 22.13 需在 WP-C 中复核），可以匹配三字及以上的子串（本次实测：`"露川-4"`、`"喜欢的"` 命中）。**两字查询不命中**（实测：`"茶叶"` 无结果）。选型探针比较了 trigram、ICU 分词、jieba 与“汉字单字 + 二元组”，结论是用 FTS5 建索引、在应用侧做“汉字单字 + 二元组 + 拉丁词”的切分，查询用 OR + bm25（[06 §2](06-selection.md)）。
- **语义向量（按需引入，[06 §3](06-selection.md)）：** 如果采用，只对它的文字建向量，不对全部档案原文建。它的文字是数千到数万条，可以在进程内暴力计算余弦，不需要 ANN 或向量数据库（例如 5 万条 × 512 维约 2.6×10⁷ 次乘加）。档案原文逐字查找仍走文本索引。

### 4.3 再激活（新增：`recall` 与浮现）

- **`recall`（主动回忆）：**
  - 对话中的工具，按查询词（可选时间范围）检索**它写下的文字**，返回文字及写下的日期。
  - 入档为 `act/recalled`（新增，需登记），记录参数与返回的 `seq`。
  - 它与 `check` 的区别写进工具说明：一个是“我当时怎么写的”，一个是“当时实际发生了什么”。
- **浮现（不由它主动发起的想起）：**
  - 组装时，用当前输入作线索，在**不在前景中**的文字里检索；
  - 最多放入少量（例如 3 条、2,000 字以内），放在原文窗口之后、当前输入之前，用自然的话呈现（例如“你想起以前写下的：”）。
  - 程序不说明它们为什么浮现。
  - 浮现可以关闭；默认是否开启，由评测结果决定。
  - 它对应 V1 运行过却从未评估的“联想闯入”，也对应蓝图中“潜在组织偏置哪些回忆被想起”的接口位置（§7）。

### 4.4 演化（新增：重整与激活）

- **重整（它自己重新组织旧文字）：**
  - 空闲时（在整理完成之后，例如每天至多一次），程序选出一组彼此相关的旧文字：一条种子，加上与它在文本、时间或人物上相关的文字，在字数上限内。
  - 交给它读，像整理一样不面向任何人。它可以重写、合并、写下新的理解，也可以什么都不写。
  - 结果入档为 `inner/wrote`；`meta` 指向这次的 `control/presented`。
  - 如果它明确表示某几条旧文字已被新写的内容包含（例如通过一次可选的工具调用，用本次请求内的编号指称），这个选择作为它的行为入档。之后组装前景时，被包含的旧文字让位，但仍可 `recall`、可 `check`。
  - 程序**不替它判断**哪些已被包含。
- **激活（存取的动力学，假设）：**
  - 前景与浮现的候选顺序，可以按访问历史计算的激活值排列：形成时间，以及被 `recall` 返回、被线索浮现的时间。
  - 一个已有理论依据的候选是 ACT-R 的基础激活 `B = ln Σ_j t_j^(−d)`，它与环境中信息的再需要概率相符（Anderson & Schooler, 1991）。
  - 只有可核验的事件参与计算，不看内容。
  - **已知风险：** 被呈现 → 激活升高 → 再被呈现，形成自我强化。因此“常规前景呈现”是否计入激活是一个实验参数；话题重复率是必测指标（§8）。
- **遗忘 = 可达性下降，不是删除。** 退出前景、不再浮现的文字仍在档案中。没有保留期，没有按类别过期。

### 4.5 参与生成（组装）

见 §5。原则：**所有记忆只经过一个组装处进入模型**；没有第二条旁路，也没有另一个“记忆服务”替模型预先回答问题。

### 4.6 更正

按决定（a），不变：

- 更正逐字入档，在窗口中可见；离开前经过整理；之后 `check` 与 `recall` 都可能返回它。
- 重整给了它一个重新理解旧说法的机会。是否改写，仍由它决定，作为观察。

### 4.7 删除（开放问题，此处只登记）

- 删改事件之后，派生索引必须排除被删内容（重建即可满足）。
- 难的是：一段**它写下的文字**如果是由被删内容形成的，是否也要删除或屏蔽？形成关系使这件事可以被精确找到。如何处理是隐私与“它自己的记忆”之间的取舍，需要负责人决定，不在当前工作包内（[05](05-decisions.md) 列为暂缓项）。

### 4.8 换模型

- 它的文字是文本，原样延续。
- 文本与结构索引不依赖模型。
- 语义向量属于某个模型空间：换嵌入模型就整体重建新的一代，旧代可以保留用于对照。
- 呈现记录中有组装规则版本与模型名，换模型前后的输入差异可以复原。

## 5. 组装：前景、窗口与浮现

| 部分 | 内容 | 上限 | 变化频率（前缀缓存） |
| --- | --- | --- | --- |
| 人设 | 文件全文 | 文件大小 | 不变 |
| 前景记忆 | 它的文字中当前处于前景的一组，按写下的时间排列 | 字数预算（现为 16,000） | **只在整理/重整之后重算**，不逐回合重排 |
| 原文窗口 | P4 的原文窗口 | N 个事件（字数不设上限，P4 §3.1） | P4 的跳跃式起点 |
| 浮现 | 由当前输入作线索的少量旧文字 | 条数与字数上限 | 每回合可能不同，因此放在靠后的位置 |
| 当前输入 | 当前这句话与现在的时间 | — | 每回合 |

- **前景如何选：**
  - P4 的规则是“最近写下的，整条放入，放满预算为止”。
  - 新规则（假设）：在“未被它表示为已包含”的文字中，按激活值选入，选入后仍按写下的时间排列。
  - 只在整理或重整后重算，以免每回合打乱前缀。
  - P4 的新近规则是对照组。
- **不截断原文与它的文字**（P4 的约定不变）。超限时如实失败并可诊断；呈现记录中的总字数用于诊断。

## 6. 工程选择

| 问题 | 选择 | 理由与可推翻条件 |
| --- | --- | --- |
| 数据库 | 继续 SQLite（`node:sqlite`，无外部服务） | 单实例、单个体；V1 的 PG 是为多进程与 Host 体系服务的。多写者或 10M 级事件时重新评估 |
| 派生索引放在哪 | 数据目录中独立的 `index.sqlite`；记录水位 `through_seq` 与规则版本；损坏或版本不符就整体重建 | 档案 schema 校验要求表结构一致；索引不进入快照的正确性前提，恢复后可重建 |
| 每回合状态 | 按 `seq` 倒序、带 `LIMIT` 的 SQL 查询取代整表解码（`archive.events()`）；不加档案索引 | 1M 事件：整表解码 45 s，倒序查询 1–5 ms；复合索引反而使两条查询退化到约 1 s（[06 §1.2](06-selection.md)） |
| 场景与分支 | 参数化，仍只启用 `web` 与 `dev:v2-dev` | 不新增场景，只消除硬编码，避免日后整体改写 |
| 中文检索 | FTS5（无内容表）+ 应用侧“汉字单字 + 二元组 + 拉丁词”切分；OR + bm25；`fts5vocab` 裁剪高频词元 | 探针：14 个查询 14/14；20 万条索引 51 MB（[06 §2](06-selection.md)） |
| 语义向量 | 按需引入：本地嵌入进程 + OpenAI 兼容 `/v1/embeddings`；只对它的文字、进程内暴力计算 | 5 万条 512 维约 87 ms；更大时用 `sqlite-vec`（[06 §3](06-selection.md)） |
| 后台任务 | 整理、重整、索引都在同一进程、同一队列中，有界重试；失败如实入档（P4 的 `control/unconsolidated` 先例） | 不需要 V1 的租约与 outbox：单实例，档案就是队列的真相 |

**性能目标（建议写进 WP 的验收）：** 1M 事件档案、假模型下，普通回合的程序开销 p95 < 100 ms；索引落后不阻塞回复；从零重建 1M 事件的索引在分钟级。

## 7. 与潜在组织研究的接口

- 蓝图把“调节过程”定义为潜在状态偏置哪些回忆被想起、注意哪个场景、等多久再说话。
- 本架构在三处留出位置，都不需要现在实现：
  1. 浮现与前景的候选排序函数接受一个可选的状态输入；
  2. 呈现记录使“潜在状态改变了它遇到什么”可以被测量；
  3. 档案 + 呈现记录是训练写入器的完整轨迹。
- 潜在组织研究可以读这些，不需要改动记忆过程。

## 8. 已验证的选择与待检验的假设

**已验证（有实测）：**

| 选择 | 证据 |
| --- | --- |
| 只追加档案、原话先入档、UNKNOWN | P1–P3 验收 |
| 离开窗口前先整理、文字随它进入对话、逐字查档 | P4 验收 D1–D21（假模型，机制层面） |
| 先排序再截断；候选受限明说；各通道独立失败 | V1 R5 实测（01 §2.2） |
| 中文需要单字/二元组；trigram 不够；FTS5 + 应用侧切分可行 | V1 R5 实测；本次选型探针（06 §2） |
| 派生索引的水位/校验/重建 | V1 R5 实测 |
| 逐字引文能抓住模型抄写错误 | V1 R5 实测 |
| 瓶颈是整表解码，不是 SQLite | P4 验收性能测量；本次 1M 事件探针（06 §1.2） |

**假设（必须经评测检验，见 [ROADMAP](../../ROADMAP.md)）：**

| 编号 | 假设 | 主要指标 | 对照 |
| --- | --- | --- | --- |
| H1 | 它自己写下的文字足以承担跨天的连续：负责人在意的事，隔天、隔周仍能被它说起 | 合成生活脚本中事实与变化的跨期召回；更正之后的说法 | V1 式第三人称事实摘录（只作离线对照，不进产品） |
| H2 | 线索浮现能找回预算之外的过去，而不增加话题闯入 | 召回增益；话题重复率；无关浮现的比例 | 关闭浮现 |
| H3 | 重整让前景更连贯、更紧凑，而不是失控漂移 | 前景覆盖的经历跨度；同一说法的重复；更正被吸收的比例 | 只有整理、没有重整 |
| H4 | 按访问历史的激活优于纯新近；自我强化可控 | 前景命中率（之后被用到的比例）；重复率 | P4 的新近规则 |
| H5 | 由作者关系连接的经历足以支撑“对人的理解” | 多人场景下对不同人的区分 | 推迟到多人场景 |
| H6 | 日常中文只用文本索引即可；向量只在换说法、跨语言时必要 | 换说法查询的漏检率 | 有/无向量 |
| H7 | 真实模型会在需要时自己用 `recall` / `check` | 需要回查的情境中的调用率；调用后的回答 | — |
| H8 | 呈现记录的开销可以忽略 | 每回合的写入量与时延 | — |

**判定规则：**

- 一个假设在评测台上**没有增益**，对应机制就不进入默认行为。
- 增益要相对对照组计算，而不是绝对值。
- 一次大规模的历史注入**不能**作为长期记忆成功的证据。评测必须按真实的时间间隔运行整理与重整（[ROADMAP](../../ROADMAP.md)）。

## 9. 对现有原则的细化（原则上采用，尚未写入）

下列细化已原则上采用（[05](05-decisions.md)），但**没有**写进 AGENTS 或 TERMS。它们在第一个用到它们的工作包的 PR 中写入：第 3、4 条随 WP-C，第 1、2、5 条随 WP-E。

1. **TERMS §2“关系 ≠ 意义”补一条：**
   - 程序可以计算相似度、排序和激活，用来决定候选与呈现顺序，条件是 §1.1 的五条；
   - 这不属于“判断这句话是什么意思”。
   - 理由：不细化，语义索引和任何动力学都会被误判为违反宗旨；而细化过宽，又会让 V1 式的打分回来。五条正是两者的分界。
2. **P4 §1“程序不摘要、不抽取、不打分”澄清为“不对内容打分”。** 按访问历史计算的激活值不评价内容。
3. **不变量 6“索引可以重建”澄清：**
   - “可重建”指能从档案和带版本的导出规则（含模型空间）重新导出，不要求逐位相同；
   - 它的文字及其形成关系在档案中，是带版本的资产，不属于索引。
4. **不变量 3 澄清：** 记录一段文字的形成关系（它读过什么），是记录关系，不是要求证据；文字内容永远不被程序校验。
5. **不变量 4 的推论（多场景之前需要定下）：**
   - 一段文字的可见范围，取它形成时所读材料中最严格的那个；
   - 浮现与 `recall` 只返回当前听众可见的文字。
   - 理由：V1 蓝图 N10 已指出潜在组织是有意的例外，而文字不是。

**不建议修改的：**

- `inner` 只有 `wrote` 一个 kind：重整的产物仍是 `inner/wrote`；回忆是行为（`act/recalled`）；呈现是控制记录（`control/presented`）。不需要新的 `inner` kind。
- 决定（a）。
- 档案只追加。
- 不从 V1 带入词汇。
