# P3　快照、校验与恢复

> 周期 C1 的最后一个工作包。实施：Sol。验收：Claude。前置：P2 已合并到 `main`（`75e6893`）。
>
> 只需读本文件、[`AGENTS.md`](../AGENTS.md) 与 [`docs/TERMS.md`](TERMS.md)。本文件与其他资料冲突时，以本文件为准。

## 1. 目标

P3 结束时，YUVI_NEXT 应当是一个可以持续使用的文字对话原型：

- **历史有副本。** 运行中自动定期生成档案快照；也可以随时手动生成。
- **副本可信。** 每份快照都能独立校验；被截断或改动过的快照会被识别出来。
- **能恢复，而且恢复不破坏任何已有数据。** 恢复只生成一个新的数据目录，不触碰原数据目录和快照；新档案如实记下“从哪份快照恢复”。
- **同一档案不被两个进程同时使用。** 档案损坏时拒绝启动，不自动修复。

**最高优先级：** 任何快照、校验、恢复或启动检查，都不能修改、删除或覆盖已存在的档案数据。

### 为什么包含单实例保护

当前 `main` 上已实测：

1. 进程 A 正在生成一个回合时，用同一个 `YUVI_DATA_DIR`、不同端口启动进程 B；
2. B 的启动恢复为 A 尚未结束的回合补记了 `control/error`（`interrupted` / `unknown`）；
3. A 随后写入 `said`。

结果，这个 `heard` 有两个终结事件，档案中出现了一个虚假的中断记录。恢复演练会让“同时启动新旧两个进程”这种情况更常见，所以单实例保护属于 P3。

## 2. 范围

### 必须完成

1. **快照。**
   - 快照是档案在某一时刻的一致副本：
     - 包含 WAL 中已提交的内容；
     - 在进程运行、回合进行中也能生成；
     - 生成时不阻塞对话。
   - 写入方式必须是原子的：不完整的快照绝不能通过校验。
   - 快照目录由 `YUVI_SNAPSHOT_DIR` 指定，默认为 `<YUVI_DATA_DIR>/snapshots`；它不能与 `YUVI_DATA_DIR` 是同一个目录。
   - 文件名包含 UTC 时间，按字典序排列即按时间排列。
   - 快照文件及其附带文件不对其他用户可读：文件权限不宽于 `0600`，目录权限不宽于 `0700`。
   - **自动快照：**
     - 服务启动时，如果最近一份快照的生成时间已超过一个间隔，或还没有快照，就生成一份；
     - 运行中，每当距最近一份快照满一个间隔，再生成一份；
     - 间隔由 `YUVI_SNAPSHOT_INTERVAL_MS` 配置，默认 `86400000`（一天）。
   - **手动快照：** `npm run snapshot`。
     - 只需要 `YUVI_DATA_DIR`（以及可选的 `YUVI_SNAPSHOT_DIR`），不需要模型配置；
     - 服务运行时也能执行；
     - 成功时输出快照路径。
   - **失败处理：**
     - 快照目录无法创建或写入时，服务拒绝启动，错误信息指出 `YUVI_SNAPSHOT_DIR`；
     - 运行中某次自动快照失败时，只在标准错误输出中给出不含密钥的固定信息；对话照常进行，下一次检查时重试。
   - 快照不写入档案。它是运维副本，不是 YUVI 的经历。
   - P3 不自动删除任何快照。
2. **校验。** 命令为 `npm run verify-snapshot -- <快照文件>`。
   - **通过**时退出码为 0，并输出事件数与最大 `seq`。
   - **不通过**时退出码非 0，并输出原因。以下任一情况都不通过：
     - 文件内容的任何一个字节被改动，或文件被截断；
     - SQLite 完整性检查失败；
     - 表结构或只追加触发器与当前程序不一致。
   - 检测字节改动的具体机制（例如附带的哈希文件）由 Sol 决定。
3. **恢复。** 命令为 `npm run restore -- <快照文件> <目标目录>`。
   - **目标目录：** 必须不存在，或存在但为空；否则拒绝，不写入任何内容。正在使用的数据目录永远不能作为目标。
   - **先校验，后写入：** 快照未通过校验时拒绝，目标目录保持不存在或为空。
   - **成功后的结果：**
     - 目标目录可以直接作为 `YUVI_DATA_DIR` 使用；
     - 其中的事件与快照中的事件逐列相同；
     - 末尾另外追加恰好一个 `control/restored` 事件（见 §3）。
   - **不触碰其他数据：** 恢复不修改快照文件，也不修改任何其他目录，包括原数据目录。
   - **不需要模型配置。**
   - 用恢复后的目录启动时，P1 的启动恢复照常处理快照中尚未结束的回合（`not_sent` / `unknown`），不重发。
4. **启动检查与单实例。**
   - **单实例：**
     - 服务进程启动后、写入任何事件之前（包括启动恢复），必须取得该数据目录的独占使用权；
     - 已有活着的进程在使用该目录时，后启动的进程以非零退出码退出，错误信息指出 `YUVI_DATA_DIR`，不写入任何事件；
     - 前一个进程被 `SIGKILL` 后遗留的状态不能阻止重新启动。
   - **完整性：**
     - 启动时检查档案完整性；
     - 检查失败时以非零退出码退出，错误信息指出 `YUVI_DATA_DIR`，并提示可以从快照恢复；
     - 不尝试修复，不自动恢复，不修改档案文件。
   - **不影响手动快照：** `npm run snapshot` 只读档案，服务运行时也能执行，不受独占限制。
5. **已有数据兼容。**
   - 不修改 `events` 表的结构与触发器，档案数据库中不新增表。
   - 由 P2（`main` 上 `75e6893`）创建的数据目录，可以直接被 P3 打开使用，不需要迁移；
   - 其中的事件保持不变。
6. **登记事件种类。** `control/restored` 已由本 PR 在 `docs/TERMS.md` 登记，实现必须与登记的含义一致。
7. **测试与说明。**
   - `npm test` 覆盖上述行为，不访问外部网络和真实模型。
   - 在 `README.md` 中写明：
     - 快照的位置与配置；
     - 三个命令的用法；
     - 一次完整恢复的操作步骤；
     - 恢复后不要再用旧目录启动同一条生活。
     - 快照只含档案；人设文件、模型配置与密钥不在快照中，恢复后需要另行提供。
   - 在 `docs/notes/P3.md` 中写明实现选择，不超过一页。

### 明确不做

- 异地或远程备份、加密、快照保留与自动清理（P7 部署时再定）；
- 合并两份档案，或恢复到快照之间的任意时间点；
- 快照或恢复相关的 HTTP 接口与网页界面；
- 备份人设文件或其他配置（它们是外部输入）；
- 改变 P1、P2 已有事件种类的含义；改变对话、上下文或用量行为；
- 记忆与整理（C2）、主动开口（C3）、V1 数据导入（P5）。

## 3. 接口与约束

| 项     | 约定                                                                                                                                                                                                                                                                                |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 命令   | `npm run snapshot`；`npm run verify-snapshot -- <file>`；`npm run restore -- <file> <dir>`。成功时退出码为 0，失败时为非 0                                                                                                                                                          |
| 配置   | 新增 `YUVI_SNAPSHOT_DIR`（默认 `<YUVI_DATA_DIR>/snapshots`）和 `YUVI_SNAPSHOT_INTERVAL_MS`（默认 `86400000`）。无效值的错误信息指出变量名，不输出值                                                                                                                                 |
| 事件   | `control/restored`：`actor="system"`，`scene="unknown"`（恢复不发生在任何对话场景里，P3 不引入新的场景值），`branch` 与快照中的事件相同，`content=""`。`meta` 至少包含 `through_seq`（快照中的最大 `seq`）、`through_id`（该事件的 `id`）和 `snapshot_sha256`（快照文件的 SHA-256） |
| 上下文 | `control/restored` 不进入模型上下文。P3 不改变上下文的组成                                                                                                                                                                                                                          |

**边界：**

- 遵守 P1 §3.6、P2 §3 的全部边界与 `AGENTS.md` 的不变量。
  - 特别是：密钥不进入快照、恢复目录和任何输出；
  - 档案只追加，恢复也只是在副本上追加。
- 不修改 `AGENTS.md`、`docs/ROADMAP.md`、`docs/TERMS.md`、`docs/P1.md`、`docs/P2.md`、`docs/P3.md`。
- 不新增运行时依赖；确有必要时，在 `docs/notes/P3.md` 中说明理由。
- Node 版本要求保持 `>=22.13.0`。

**由 Sol 决定：**

- 快照方式（例如 `VACUUM INTO`、备份接口或其他一致复制方式）；
- 附带文件的格式与校验机制；
- 独占使用权的实现方式；
- 启动完整性检查的具体方式；
- 命令入口与代码结构；
- 自动快照的定时方式。
