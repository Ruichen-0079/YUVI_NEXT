# P9 实施说明

- 复用 P8 派生索引、词元与全索引 DF；`index.sqlite` 升级至 `format=2`，新增 `term_df(term_hash BLOB PRIMARY KEY, doc INTEGER NOT NULL) WITHOUT ROWID`（32 字节 SHA-256 哈希键，满足普通表字段 ≤256 字节约束且不保存词元原文）以 O(1) 替代 `fts5vocab` 倒排扫描，并新增部分覆盖索引 `docs_wrote(seq) WHERE kind='wrote'` 加速仅查文字的过滤；旧 `format=1` 索引启动校验报 `version` 后自动重建，`index verify --full` 校验 `term_df` 与 `vocab` 的逐词一一对应。recall 在原有查询上加 wrote 过滤及 10/8000 预算，扫描线程使用相同过滤。没有档案 schema、索引、触发器或依赖变更，不改变切分、DF 定义、裁剪、BM25 排序或选取语义。
- UTF-8 超过 16 KiB 的词元在派生索引内用带前缀的 SHA-256 摘要编码，清单保留原词元。索引在写入文档的同一事务更新 `doc_count`，并用它校验 DF 取值范围。
- 浮现作为对话第 0 步的有界选择，最多读取 20 个候选原文；先核对来源身份、场景、分支，再按范围与预算排除。选中后由同一组装入口生成消息与清单，续步冻结，重建只用历史引用，不重算候选。
- p7/p8 历史规则保持原样；两项关闭时的进程级对照比较完整请求、事件、SSE 和 usage。P8 基线命令显式关闭两项能力，避免把默认新增工具混入旧契约。
- 独立统计读取档案，按引用判断是否实际呈现；假模型仅按冻结策略摘抄和调用工具，不提供语义能力证据。W 形态独立生成，未改变 P8 varied 或两段冻结生活。
- P9-R 驱动只在回环假模型下验证。授权与明确额度先于凭据和网络；usage 缺失时停止。预算护栏按提供方事后返回的 `usage` 累计，最后一个在途请求最多可能超出限额一次（输入无法预先截断，输出虽按剩余额度传 `max_tokens` 仍以提供方返回 `usage` 为准），必须在获授权的真实实验中预留至少单个请求的额度余量。

正式裁定后的固定提示语为“你以前写下的：”；C7 对任意输入检查结构字节，冻结检验与九周基线另检查完整字节。检索词原样保留，旧开发提示语不增设历史兼容分支。

最终测试、性能、自查和研究数字见本 PR 的配套报告；本说明不替代原始证据。

观察口径：规划 `surface_sim.py` 额外要求最低 DF 大于 0，正式 P9 只在无词元或最低 DF 超过 C 时跳过。因此正式实现不会因某个词元未出现过而忽略同一句中其余已出现的词元。基线的实际浮现率可能与规划模拟明显不同；不为追随规划数字改变冻结规则，使用逐回合独立 FTS 重建核对实际结果。
