# P9 实施说明

- 复用 P8 派生索引、词元与全索引 DF；recall 在原有查询上加 wrote 过滤及 10/8000 预算，扫描线程使用相同过滤。没有档案 schema、索引、触发器或依赖变更。
- 浮现作为对话第 0 步的有界选择，最多读取 20 个候选原文；先核对来源身份、场景、分支，再按范围与预算排除。选中后由同一组装入口生成消息与清单，续步冻结，重建只用历史引用，不重算候选。
- p7/p8 历史规则保持原样；两项关闭时的进程级对照比较完整请求、事件、SSE 和 usage。P8 基线命令显式关闭两项能力，避免把默认新增工具混入旧契约。
- 独立统计读取档案，按引用判断是否实际呈现；假模型仅按冻结策略摘抄和调用工具，不提供语义能力证据。W 形态独立生成，未改变 P8 varied 或两段冻结生活。
- P9-R 驱动只在回环假模型下验证。授权与明确额度先于凭据和网络；usage 缺失时停止。单个在途请求的输入费用无法用提供方事后 usage 预先精确约束，必须在获授权的真实实验中保留额度余量。

最终测试、性能、自查和研究数字见本 PR 的配套报告；本说明不替代原始证据。

观察口径：规划 `surface_sim.py` 额外要求最低 DF 大于 0，正式 P9 只在无词元或最低 DF 超过 C 时跳过。因此正式实现不会因某个词元未出现过而忽略同一句中其余已出现的词元。基线的实际浮现率可能与规划模拟明显不同；不为追随规划数字改变冻结规则，使用逐回合独立 FTS 重建核对实际结果。
