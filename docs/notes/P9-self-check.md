## 规格阻塞及限制

1. C7 的硬上限与合法长词原样记录不可同时满足。最小组装样例5,778字节，真实服务样例5,786字节且正常完成：[PR证据与建议](https://github.com/Ruichen-0079/YUVI_NEXT/pull/23#issuecomment-6622270527)。建议明确超长词边界或正式规定另一种清单表示；Sol 不自行截词、改变输入接受规则或降低门槛。
2. 固定浮现提示“你想起以前写下的”仍按正式规格保留：[措辞澄清请求](https://github.com/Ruichen-0079/YUVI_NEXT/pull/23#issuecomment-6621943503)。不擅自修改冻结文件。
3. P9-R 未获费用授权。预算以提供方返回 usage 为准，单个在途请求的输入可能超过限额；无用量不继续。真实模型协议、质量、费用与研究结论均未实测。
4. 全集 show 审计逐条调用现有诊断，life-b 每臂约14–18分钟；属于离线审计成本，不是回合开销，未为此扩建缓存或修改 P7 诊断机制。
5. Node22 两个版本执行的 npm12 有兼容性提示；实际使用对应 Node 运行构建和195项测试均成功。没有更换运行时依赖。

没有修改被冻结的规划文件（仅整合负责人指定的正式规格提交），没有实施 WP-F/G。长期基线、百万语料、手动重现与被中断的长跑保留在忽略的本机目录中，未自动清空；常规自动化单测仍清理各自临时夹具。C7 裁定前不转 Ready，不请求最终验收或自行合并。
