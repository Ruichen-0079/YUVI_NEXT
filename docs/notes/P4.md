# P4 实施说明

- 整理与对话共用一个串行 Promise 队列。独立的收件队列即时保存消息；定时器只在无回合时入队整理。空闲检查最多每秒一次；模型失败后从失败结束起固定退避 30 秒，退避只属于本次运行，不写伪造事件。空输出和长度停止都正常入档；进程中断的整理没有进度，重启重新读取原材料。
- 进度 C 取 wrote/unconsolidated 材料终点最大值。材料在首个未结束 heard 前截断，每批最多 N。原文窗口目标起点按对话事件位置以 N 为步长推进（不少于 ceil(N/2)）；实际起点不能超过 C。压力时先整理到能够前进；失败期间保留全部未覆盖事件。已结束积压超过 2N 时先记录最早 N 个的 unconsolidated，再前进。所有位置从档案计算，无旁路游标；恢复沿用同一计算。
- 内部文字按 JavaScript 字符串长度，从新到旧连续整条选择（默认 16000 字），最新一条始终选入；按时间顺序放在原文前。程序不解析文字含义。所有原文直接拼接；时间、作者和长度停止说明在原文外。assistant 内容仅为原话，当前时间只放在末尾指示。
- check 使用区分大小写、不拆词的字面子串；日期包含端点，无时区按本地时区，日期值表示当地午夜。只返回 heard/said/silent 和非空 wrote，最多 40 条、16000 字，最新匹配始终整条返回。沉默记录中如有理由，查阅时附原样理由；对话上下文仍只呈现没有回复的事实。无效参数不查询，checked 标明 invalid。
- 每回合至多四次请求，保留流式工具调用标识并提交协议要求的工具结果。文字跨步直接拼接，首次推出前仅记录一次发送尝试。一个有多次查阅的步骤把 usage 放在第一条 checked，其余步骤记在终结事件；整理记在 wrote。汇总覆盖所有用量事件，回合数只统计终结事件。失败请求记录字符数和 HTTP 状态码，不保存提供方错误体。
- 没有新增依赖、数据表或锁机制；P3 快照与恢复自然包含新事件及其进度。全文档案扫描用于当前单场景原型，未引入检索索引。外部模型实际行为与缓存收益尚待独立实机观察。
