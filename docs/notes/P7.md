# P7 实施说明

统一入口在 context.ts：P6 有界选择与纯呈现分开，显式输入 now、时区与 Node 主版本，同次产生 messages、请求参数和清单。后续步骤冻结第 0 步基础消息，只追加工具往返，并记录自己的 now/previous。server 不再构造 Message；streamModel 前先提交 presented，组装/写入失败为致命存储故障。P6 数字状态、选择规则、schema 和工具定义均未改。

只读诊断集中在 presented.ts，经 maintenance/npm 入口使用，不加载凭据或取得服务锁。一次有序扫描归结局，只留未决请求；文字范围差分计数。show 从历史范围、previous、时间、预算和工具引用重建，仅声称 messages 精确；人设、Node、规则或摘要条件不足时明确拒绝。Node 22 的 current-heard 指示取完整 UTF-8 原字节，窗口仍沿用 P6 解码，正确保留 NUL 两条路径的差异。

Linux / Node 22.23.3，离线真实服务、假模型及 Chromium：**76/76 测试通过，无跳过，81.90 秒**（[日志](P7-tests.txt)）。包括 13 种请求级跨版本状态、完整 JSON 字节、seq/UUID 引用映射、逐条 CLI 重建、异常/中断/恢复、存储失败及原有回归。两个负向边界测试成功只证明诚实诊断，不代表对应正式条件通过。

两种百万形态：普通程序 p95 **5.31 / 4.94 ms**；分项每请求增量 p95 **4.77 / 2.42 ms**，含组装/哈希/清单序列化/提交并减旧版组装，哈希不能再重复相加。提交长尾约 20/31 ms 未剔除；负的端到端差值仅是噪声，不宣称加速。第 0 步清单最大 **772 / 675 字节**。带呈现记录的百万档案有 267109 条清单，summary/writings **1.96 / 2.17 秒**，原生峰值 RSS **99.43 / 101.86 MB**。每天 200 单步回合仅 meta 约154/134 kB；按本次混合比例 meta 约195/171 kB，页面增量约317/266 kB，均为样本估算。[原始性能数据](P7-results.json)，命令与限制见 README/PR。

**两项正式未满足，待 Claude 澄清，不报 G1–G8 全过：**

- **G4：** 孤立 UTF-16 代理项在 P6 SQLite 绑定时已变成 U+FFFD，但原请求指示可能保留原码元，无法从档案无损恢复，show 如实 mismatch。[两版真实进程证据](P7-unicode-boundary.json)。建议明确“源档案无损保留所需原文”的前提；未改输入、原事件或清单上限。
- **G6：** SQLite readonly 在关闭 WAL 目录可能创建/初始化 WAL/SHM；主库、服务锁与事件不变。活跃服务字节/mtime 和百万诊断性能均通过，但“任何情况下不写任何文件”未满足。[实际命令证据](P7-readonly-sidecar.json)、[SQLite 说明](https://sqlite.org/wal.html#read_only_databases)。建议允许必要的原生协调元数据；未用 immutable 忽略 WAL，未扩建副本、VFS 或锁框架。

冻结规划、依赖及存储结构均未改；不实现 WP-C 及后续机制。两项澄清尚未获批，交付 PR 为 Draft。
