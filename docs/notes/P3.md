# P3 实施说明

- 不改 events 表、触发器或上下文；DDL 仅抽到 schema.ts，校验时对照当前 DDL 的 sqlite_master 定义（规范化空白），同时执行 integrity_check。已有档案在持有原服务锁后先只读检查；失败不打开可写连接，不修复。SIGTERM/SIGINT 关闭档案；SIGKILL 后仍由既有机制恢复。
- 手动/自动快照均用独立只读 SQLite 连接执行 VACUUM INTO，包含 WAL 提交。自动任务在独立 Node 子进程运行，只传数据/快照目录与间隔，不传模型配置或密钥；按最近可验证快照时间安排下一次检查，失败固定报错并在最多一秒后重试。启动先检查快照目录可写，再恢复回合；第二实例在此前由 PR #7 拒绝。
- 私有 .building-* 目录内生成预建0600数据库、转换为独立DELETE日志模式、校验并生成 .sqlite.json 清单（版本、UTC时间、SHA-256、事件数、边界ID/序号、分支）。fsync文件后用不覆盖的硬链接依次发布数据库和清单，再fsync目录；清单是提交标记，无清单绝不通过验证。进程被杀可能留下私有临时目录/未发布完成文件，不自动删除这些遗留物或已发布快照。文件名为UTC毫秒时间加UUID；同毫秒内不承诺UUID先后。
- 恢复先校验，再在目标同级0700临时目录生成0600副本，复核SHA，追加一条control/restored（scene=unknown），fsync后rename发布；Linux上不能替换非空目录，service.lock的存在也阻止发布。父目录须已存在；已有目标只接受直接的空目录，不接受符号链接。维护命令不取得、创建或修改service.lock。空档案through_seq=0，through_id/branch=unknown，不猜值。
- 新目录0700、快照/清单/恢复文件0600，服务umask=077；已有快照目录收紧为0700。快照目录真实路径不能等于数据目录。间隔须为1–2147483647整数毫秒。仅备份档案；不含人设、环境配置或密钥，无新依赖。
- 测试用真实服务/命令与回环假模型，覆盖运行中快照、恢复与拒绝、损坏启动字节不变、10万事件下10次真实SIGKILL、权限及P1/P2回归。范围与验收接口无变更，未实施P4；哈希识别损坏，不作为外部签名或认证。
