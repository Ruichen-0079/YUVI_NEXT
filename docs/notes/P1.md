# P1 实施说明

- Node 22.13+、TypeScript，使用内置 HTTP、fetch、`node:sqlite`；无运行时第三方依赖。SQLite 文件为 `YUVI_DATA_DIR/archive.sqlite`，WAL + `synchronous=FULL`。触发器拒绝 UPDATE、DELETE 及以 REPLACE 覆盖事件。
- 入档队列与生成队列分开：请求按到达顺序验证、持久化 `heard` 并发出其 ID；即使正在生成，后续已接受消息也已入档。生成严格串行。上下文以 seq 排序，只取 heard/said；正在处理的回合不读取排在它之后的 heard，下一回合可看到之前已完成的 said。作者用 user/assistant 角色表达，人设全文原样作为 system。
- 模型请求为 POST `<base>/chat/completions`。**总超时 30 秒**（包括连接与读取整个流）；失败只给固定错误，不记录上游异常、响应体或密钥。首个非空增量前同步提交 reply_attempt；收到 `[DONE]` 才提交 said。合法但没有文本的完整流也记录空回复及对应 attempt，不把它当成中断。
- 启动只处理没有终结事件的 heard：按是否存在 attempt 记录 not_sent/unknown，不重发，不推断部分内容。客户端断开时继续已有生成，档案表示发送尝试与模型完整生成，不能证明浏览器已收到。数据库写入失败关闭服务，保留未完成事件供下次启动处理。
- `npm test` 的假模型只监听 127.0.0.1；A8/A8b 使用子进程实际 SIGKILL。设置 `YUVI_CHROMIUM` 后同一命令也运行浏览器检查；无浏览器时明确跳过该项。安装依赖不下载 Chromium。
- 范围/验收接口无改动。实施起点 main 仅有初始 README；AGENTS.md 与 docs/P1.md 从初始化 PR #1 读取，未复制或修改受保护文档。初始化 PR 需由负责人合并；合并时 README 可能需保留双方内容。未增加 P2 功能或额外架构文档。
