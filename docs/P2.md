# P2　能沉默、能用真实模型日常使用的对话回合

> 周期 C1 的第二个工作包。实施：Sol。验收：Claude。前置：P1 已合并到 `main`。
>
> 只需读本文件、[`AGENTS.md`](../AGENTS.md) 与 [`docs/TERMS.md`](TERMS.md)。本文件与其他资料冲突时，以本文件为准。

## 1. 目标

P1 让 YUVI 能在浏览器里对话。P2 补上 P1 验收时发现的、阻碍日常使用的三件事：

1. **它可以选择不回复。** 沉默是它的行为，作为 `act/silent` 写进档案，与失败（`control/error`）区分开。这也是第一次让模型通过工具调用表达一个选择。
2. **真实模型下可用。**
   - 较长的回复不会因为一个总时长上限被截断；
   - 消息排队时，模型知道自己正在回应哪一条；
   - 启动失败时，能看出是哪个配置项有问题。
3. **用量可见。** 每次模型调用的 token 用量被如实记录，可以按天查看。

**不是研究功能。** 沉默在这里只是一个可记录的行为选项。P2 不判断“什么时候该沉默”，也不教模型什么时候该沉默。

## 2. 范围

### 必须完成

1. **沉默工具。**
   - 每次模型请求都提供一个名为 `stay_silent` 的工具（OpenAI 兼容的 `tools` 格式），参数为可选的字符串 `reason`，`tool_choice` 为 `auto`。
   - 回合的结局按下表确定：

     | 模型的输出                           | 回合结局                                                                                        |
     | ------------------------------------ | ----------------------------------------------------------------------------------------------- |
     | 没有文本，调用了 `stay_silent`       | 写入 `act/silent`：`reply_to` 指向 `heard`，`content` 为 `reason`（没有则为空串），`model` 必填 |
     | 有文本（无论是否调用了工具）         | 与 P1 相同，以 `act/said` 结束；被忽略的工具调用记在 `said.meta.ignored_tools`（工具名数组）    |
     | 没有文本，也没有工具调用，流正常结束 | 与 P1 相同（`reply_attempt` + 空 `said`）                                                       |
     | 失败或中断                           | 与 P1 相同                                                                                      |

   - 沉默时不写 `reply_attempt`，因为没有任何内容对外发送。
   - SSE 以 `event: silent` 结束，`data` 为该事件的 `id`。
   - 网页把它显示为“（没有回复）”或类似的中性文字，不加解释。

2. **恢复与上下文认识沉默。**
   - 启动恢复时，带有 `act/silent` 的 `heard` 视为已有结局，不再补记 `control/error`。
   - 之后回合的上下文中，`act/silent` 可以辨认为“这一回合它没有回复”。它不能被呈现为一条发给对方的消息，也不能和 `said` 混淆。
   - 具体呈现方式由 Sol 决定。
3. **空闲超时。**
   - 去掉 P1 的“整条流 30 秒总超时”。改为两个限制，都可以用环境变量配置：
     - 两次收到数据之间的最长间隔（`YUVI_MODEL_IDLE_TIMEOUT_MS`，默认 `60000`，含等待第一个字节）；
     - 一次调用的总时长上限（`YUVI_MODEL_MAX_DURATION_MS`，默认 `600000`）。
   - 超时的记录方式与 P1 的模型失败相同（`not_sent` / `partial`）。
4. **回合锚定。**
   - **事件按档案中的真实先后呈现，不得为了凑成一问一答而重排。** 例如“甲”“乙”先后到达、对“甲”的回复在“乙”之后才写入，上下文里就是甲、乙、对甲的回复。
   - 在按时间排列的事件之后，追加一条 `user` 角色的**回合指示**，写明这一回合回应的是哪条 `heard`。只能用可核验的关系来指明：时间、作者、`id` / 序号，可引用原文；不加入语义标注，也不改写原文。
   - 回合指示由程序在每次请求时生成，不写入档案。
   - 指示的措辞与格式由 Sol 决定。
5. **用量记录。**
   - 请求时设置 `stream_options: {"include_usage": true}`。
   - 提供方返回的 `usage` 对象原样写入该回合**终结事件**（`said` / `silent` / `error`）的 `meta.usage`。
   - 提供方没有返回时，不写这个字段，不估算。
   - 新增 `GET /api/usage`：按 UTC 日期汇总，每天给出：
     - 当日结束的回合数 `turns`（终结事件 `said` / `silent` / `error` 的数量）；
     - 其中带有 `meta.usage` 的回合数 `turns_with_usage`；
     - `prompt_tokens` 之和、`completion_tokens` 之和；
     - 提供方返回的其他数值字段之和（例如缓存命中）。
   - 不计算金额。
6. **启动错误可定位。**
   - 配置缺失或无效时，错误信息指出变量名（例如 `Missing required configuration: YUVI_MODEL`）。
   - 不输出变量的值，以免泄露密钥。
7. **登记事件种类。** `act/silent` 已由本 PR 在 `docs/TERMS.md` 登记，实现必须与登记的含义一致。
8. **测试与说明。**
   - `npm test` 覆盖上述行为，不访问外部网络和真实模型。
   - 更新 `README.md` 中受影响的配置与接口说明。
   - 在 `docs/notes/P2.md` 写明实现选择（不超过一页）。

### 明确不做

- 其他工具（`check`、`recall`、心意等）以及多步工具循环；
- 记忆与整理；主动开口；
- 金额计算与预算上限；
- 备份与快照（P3）；部署；
- 改变 P1 已有事件种类的含义；
- 对“什么时候该沉默”的任何提示词工程或规则。

## 3. 接口与约束

**新增或变化的对外约定：**

| 项   | 约定                                                                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 工具 | 名称 `stay_silent`，参数 `{ reason?: string }`                                                                                                                                            |
| 事件 | `act/silent`，字段与 P1 事件相同；`actor="yuvi"`                                                                                                                                          |
| SSE  | 新增终结事件 `event: silent`（`data` 为事件 `id`）；其余与 P1 相同                                                                                                                        |
| 用量 | 终结事件的 `meta.usage`（提供方原样）；`GET /api/usage` 返回 `[{ "date": "YYYY-MM-DD", "turns": n, "turns_with_usage": n, "prompt_tokens": n, "completion_tokens": n, ... }]`，按日期升序 |
| 配置 | 新增 `YUVI_MODEL_IDLE_TIMEOUT_MS`、`YUVI_MODEL_MAX_DURATION_MS`                                                                                                                           |

**边界：**

- 遵守 P1 §3.6 的全部边界与 `AGENTS.md` 的不变量。
- 不修改 `AGENTS.md`、`docs/ROADMAP.md`、`docs/TERMS.md`、`docs/P1.md`、`docs/P2.md`。

**由 Sol 决定：**

- 工具调用的流式解析方式；
- 上下文中沉默的呈现方式；回合指示的措辞与格式；
- `/api/usage` 的计算方式（查询档案或另存均可，结果必须与档案中的 `meta.usage` 一致）；
- 代码结构。
