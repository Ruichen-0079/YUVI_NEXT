# YUVI V2 周期路线图

> 2026-10-20 起草，2026-10-21 移入 YUVI_NEXT 并修订 Alice 切换时机。研究宗旨与架构背景见 [V2 蓝图](https://github.com/Ruichen-0079/YUVI/blob/cc05c14f6cc61c48079e45ad3b807976a73702e5/docs/v2/YUVI_V2_BLUEPRINT.md)（YUVI PR #339），本文件取代其中 §3.7–3.8 的阶段安排。
>
> **分工：**
>
> - 项目负责人：方向、重大架构、真实数据 / 身份 / 外部权限。
> - Claude：周期规划、工作包（P）定义、独立验收。
> - Sol：后端实现。
>
> **工作方式：** 一个周期由 1–3 个 P 组成；每个 P 是一个对 `main` 的 PR，验收标准写在 `docs/P<n>.md` 中，事先确定。

## 1. V1 的能力，按真实状态分四类

| 类别                         | 能力                                                                                                                                                                                       | V2 怎么对待                                                    |

**V2 真正新增的研究能力：**

- 不预设语义的潜在组织（心境）；
- 重建式记忆（档案与记忆分开）；
- 它自己的世界与自由时间；
- 私人场景；
- 换模型后的连续性。

**说明：**

- **时间是估计。** 前提是 Sol 每个 P 一次通过；返工按实际情况顺延，不压缩验收。
- **研究不阻塞产品。** 潜在组织的离线实验（蓝图 X12、X13）可以从 C2 起作为不阻塞的旁路开始：它只读 `v2-dev` 的副本，不改产品代码。是否开始，由你决定。
- **研究宗旨在 C1–C6 中的落实方式是“不堵死”，不需要额外工作量：**
  - 档案从第一天起就有 `inner` / `control` 类别和 `branch` 字段；
  - 程序不加任何情绪、意图、重要性标注；
  - `recall` 返回它自己的回忆，不是档案原文；
  - 事件预留潜在状态的引用位置。
- **测试、部署与数据保护**随每个 P 一起交付，不单列周期，也不作为延期理由。

## 3. Alice 切换的时机与条件

**为什么不在 QQ 接入完成后切换。**

- Alice 不只生活在 QQ 里。她在 V1 中同时有桌面上的语音、声纹识别、形象和看图能力，这些都是你实际在用的。
- 只切 QQ，会让同一个 Alice 分成两段生活：V1 桌面一段，V2 QQ 一段。这违反“一个个体同时只有一条对外生活”的原则。
- 先切 QQ、后补身体，等于默认接受数周的功能倒退。

所以 C4 只在测试身份下验证 QQ 能力，正式切换放在 C6，并且一次完成。

**切换条件（全部满足才进入 C6 的操作）：**

1. **能力对等。** V1 实际在用的每项能力，都有已验收的 V2 对应：文字对话、跨天记忆与纠正、主动开口与沉默、QQ 私聊与群、语音输入与声纹、语音输出、Live2D、看图。
2. **你确认不倒退。** 你把 V2 当主力使用至少 1 周（桌面 + 测试群），确认日常体验不低于 V1。若有你愿意接受的差距，逐项写进 P13 的切换清单，由你签字。
3. **数据与恢复。**
   - 在切换前做一次增量导出，并验证可恢复；
   - V2 的备份恢复演练通过；
   - 有写明步骤的回退方案（V1 保持可启动）。
4. **你批准。**

**例外：** 如果你主动决定提前切换某一部分（例如只切 QQ），这是你的决定，需在 P13 中写明接受的倒退项和持续时间，不是路线图的默认安排。

## 4. 每个 P 的固定格式

- **P 文件：** 目标、范围（做 / 不做）、对外接口与约束、验收标准、交付约定，一页到两页。
- **验收标准在交给 Sol 前确定。** Sol 可以因真实的技术障碍提出修改，并说明原因：
  - 不涉及范围的修改，由 Claude 决定，并在 P 文件中标注日期；
  - 涉及范围或架构的修改，交给你决定。
- **Claude 的验收：**
  - 检出 PR 分支，独立运行 P 文件中的检查（用 Claude 自己写的脚本与假模型服务）；
  - 审阅代码是否违反 [`AGENTS.md`](../AGENTS.md) 中的不变量；
  - 在 PR 评论中记录结果：通过 / 不通过，以及不通过时对应的检查项与复现命令。
- **不在验收中提出新要求。** 发现的范围外问题，记为下一个 P 的候选。
- **合并：** 验收通过后由你合并。
