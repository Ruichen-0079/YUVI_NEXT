## 1. 方向

- **YUVI_NEXT 是一个新的个体**，不是 Alice 或旧 Yuvi 的延续：
  - 不导入 V1 生活档案；
  - 不做 Alice 切换；
  - 不要求负责人承担半成品的日常陪伴成本。
- **现阶段的主线是建成一个能被检验的记忆过程：**
  - 经历形成记忆；
  - 记忆被存取、被重新激活、被它自己重新组织；
  - 每一次参与生成都可以事后看到。
  - 主动生活、QQ、身体放在它之后。
- **第一代工程方案：合理、可替换、可验证，不追求一步到位。**
  - 自由文字是当前主要的记忆载体，ACT-R 式激活是初始研究机制；
  - 二者都不排斥以后的其他表示与动力学模型。
- **通用能力用成熟组件，创造力用在 YUVI 自己的机制上。**
  - 这一阶段需要的成熟组件（SQLite 及其 FTS5、ICU、`node:test` 的模拟时钟）已经在 Node 运行时里，WP-A～WP-F 不新增依赖；
  - 语义向量需要时引入本地嵌入进程（[06 §0](research/memory/06-selection.md)）。

## 3. 工作包

工作量是 Sol 的工作日估计，含测试；P1–P4 的实际交付约为每个 P 1–2 天。每个工作包都写明它的产出由谁消费。

### WP-A　档案存取增量化（[P6](P6.md)）

- **前置：** 无。
- **产出：**
  - 回合、整理与查档路径不再读取并解码整张事件表，改为按 `seq` 倒序、带 `LIMIT` 的 SQL 查询；
  - `scene`、`branch` 由常量改为参数（仍只启用 `web` 与 `dev:v2-dev`）；
  - 一个可复用的 100 万事件合成档案生成器（测试辅助）。
- **消费者：** 所有后续工作包。没有它，任何规模测量都不可信。
- **技术路线：**
  - 只用 `node:sqlite`；
  - **不新增档案索引，不改档案 schema**：选型探针显示倒序查询单项 1–5 ms，而一个看似合理的复合索引让两条查询退化到约 1 s（[06 §1.2](research/memory/06-selection.md)）。
- **验收：**
  - P1–P4 全部回归不变（含 P4 的 D1–D21 独立脚本）；
  - 100 万事件、假模型下，普通回合的程序开销 p95 < 100 ms（现为 10 万事件 3–5 s）；
  - `check` 的耗时如实记录（最坏约 0.4 s，由 WP-C 解决）；
  - 档案 schema 不变。
- **工作量：** 1–2 天。**风险：** 低。

### WP-B　统一组装与呈现记录（[P7](P7.md)）

- **前置：** WP-A。
- **产出：**
  - 对话与整理请求由同一个组装处生成；
  - 每次请求前写一条 `control/presented`（在 TERMS 登记），记录前景、原文窗口、各部分字数与总字数、组装规则版本；
  - 一个只读维护命令：统计每段文字被呈现的次数与时间。
- **消费者：**
  - WP-D 的指标；
  - WP-F 的激活（访问历史的来源）；
  - 研究者复原任何一次生成的输入。
- **技术路线：** 无新依赖。
- **验收：**
  - 请求内容与现在逐字节一致；
  - 记录与假模型服务端实际收到的请求一致；
  - 每回合额外写入量与时延作为实测写进 PR；
  - 呈现记录不进入任何模型上下文。
- **工作量：** 1–2 天。**风险：** 低。

### WP-C　派生索引与查档升级

- **前置：** WP-A（与 WP-B 无技术依赖，可以在 WP-B 之前或并行）。
- **产出：**
  - 数据目录中独立的 `index.sqlite`：对话事件与它写下的文字的全文索引，加上时间、作者、场景。
  - 索引元数据记录：已索引到的 `seq`、切分规则版本；版本不符或校验失败时整体重建；提供 `verify` / `rebuild` 维护命令。
  - `check` 改走索引：
    - 按相关度选出、按时间呈现；
    - 匹配总数如实给出；结果受限时明说；
    - 参数与返回格式向后兼容。
  - 快照与恢复不依赖索引，恢复后自动重建。
- **消费者：** `check`（立即）；WP-E 的 `recall` 与浮现。
- **技术路线**（[06 §2](research/memory/06-selection.md)）：
  - SQLite FTS5 无内容表（`content=''`、`contentless_delete=1`），bm25 排序；
  - 应用侧切分为“汉字单字 + 相邻二元组 + 拉丁词与数字”；
  - 查询用 OR + bm25；用内置 `fts5vocab` 的文档频率裁剪过于常见的词元；
  - **不自写倒排、排序与合并，不引入分词库。**
- **验收：**
  - 一套冻结的查询集，每条有标准答案：两字词、单字、标识、中英混合、长文尾部、被高频干扰包围的旧事实、自然问句、换说法。从选型探针的 14 个查询扩充，失败如实保留；换说法预期失败，作为 WP-G 的基线。
  - 人为损坏或删除索引能检出并重建；
  - 100 万事件的重建时间、索引大小、查询 p95 作为实测；
  - 低选择性查询有上限、不卡住回合；
  - P6 验收遗留：罕见词只匹配到早期事件时不再两次全表扫描；`check` 步骤在 100 万事件档案上的耗时重新给出有依据的门槛；
  - P4 的 `check` 验收项全部仍通过；
  - 在 `package.json` 允许的最低 Node 版本上复核 FTS5 可用。
- **工作量：** 2–3 天。**风险：** 中低（切分精度；有升级路径：加入 `Intl.Segmenter` 的词）。

### WP-D　评测的最小共用部分

- **前置：** WP-B（指标读呈现记录），WP-A 的合成档案生成器。
- **产出（研究代码，不进入产品路径）：**
  - 合成生活脚本的格式与一个生成器：反复出现的话题、会变化的事实、更正、多次提到的人、长时间空白、无关日常；每个可检验点带标准答案；同一种子可复现。
  - 驱动器：在进程内启动服务，用 `node:test` 的 `mock.timers` 推进 `Date` 与计时器，让整理在每段空闲中真实发生；模型用现有的本地假模型服务。
  - 读档案与呈现记录的统计查询：跨期召回点是否被呈现、文字的消费覆盖率、话题重复率、每回合用量。
- **不做：** 通用实验平台。每个机制的对照实验写在它自己的工作包里，复用这里的三件东西。
- **消费者：** WP-E、WP-F 的验收。
- **技术路线：** `node:test` + 模拟时钟（选型探针已验证 7 天推进）；无新依赖。
- **验收：**
  - 假模型下 8 周合成生活在 CI 时间内跑完；
  - 指标可复算；
  - 同一种子输出一致。
- **工作量：** 1–2 天。**风险：** 中（指标效度；负责人审阅脚本样例）。

### WP-E　回忆与浮现

- **前置：** WP-B、WP-C、WP-D。
- **产出：**
  - `recall` 工具（检索它写下的文字，按查询与时间），入档 `act/recalled`；
  - 线索浮现：用当前输入在不在前景中的文字里检索，少量放在原文窗口之后（可配置，默认关闭），进入呈现记录；
  - 只返回当前场景可见的文字（[03 §9](research/memory/03-architecture.md) 第 5 条，随本包写入 TERMS）。
- **消费者：** 对话中的它自己；WP-F 的激活。
- **验收：**
  - 假模型下机制正确：调用入档、返回与呈现记录一致、上限生效；
  - 真实模型小规模对照（每次运行前报批预算）：浮现开/关、新近对照，记录假设 H1、H2、H7 的结果；
  - 是否默认开启浮现，依结果决定。
- **工作量：** 2–3 天，另加真实模型评测的等待。**风险：** 中（真实模型是否会用 `recall`）。

### WP-F　重整与激活

- **前置：** WP-E。
- **产出：**
  - **重整：** 空闲时选出一组相关的旧文字交给它重新理解；产物为 `inner/wrote`；它可以选择表示哪些旧文字已被新写的内容包含，这个选择入档（在 TERMS 登记）。
  - **激活：** 前景按访问历史的激活选入，可配置，P4 的新近规则为对照；前景只在整理或重整后重算，保持前缀稳定。
- **技术路线**（[06 §4](research/memory/06-selection.md)）：
  - ACT-R 基础激活 `B = ln Σ t_j^(−d)` 直接按公式实现；访问历史长时用 Petrov (2006) 近似；单元测试的参考值用 pyactr 独立算出；
  - 后台执行复用 P4 的串行队列与空闲计时器，持久状态只来自档案；
  - 无新依赖。
- **验收：**
  - 假模型下机制正确；
  - 8 周以上合成生活的对照（H3、H4），包含自我强化与漂移的指标；
  - 默认行为由结果决定。“无增益”是有效结论，此时对应机制不进入默认行为。
- **工作量：** 3–4 天。**风险：** 高（研究问题）。

### WP-G　语义向量（条件性）

- **触发条件：** WP-C/WP-E 的评测显示换说法、跨语言的漏检显著。
- **前置：** WP-C、WP-E 的评测结果。
- **产出：**
  - 通过 OpenAI 兼容的 `/v1/embeddings` 调用本地嵌入进程（llama.cpp `llama-server` 或 Ollama，模型 Qwen3-Embedding-0.6B）；
  - 只对它写下的文字建向量，以 BLOB 存在 `index.sqlite`，按模型空间分代；
  - 进程内暴力余弦，与文本通道融合；
  - 有 / 无向量的对照。
- **技术路线：** 不引入向量数据库；文字超过约 5 万条时换 `sqlite-vec`（[06 §3](research/memory/06-selection.md)）。
- **验收：**
  - 换说法查询集的漏检率下降，文本查询集不退化；
  - 换模型空间后整体重建；
  - 嵌入进程不可用时如实降级为文本通道。
- **工作量：** 2–3 天。**风险：** 中（多一个进程的部署与监控）。

### 运行与部署（旧路线中的 P7，在日常使用之前）

- **前置：** 无技术前置；在负责人开始日常使用之前完成。
- **产出：**
  - 升级到 Node 24 LTS（Node 22 于 2027-04-30 EOL）并复跑全部测试；同时确认 Node 22 读回 TEXT 时在 NUL 处截断的既有行为（P1 起存在，P6 保留）在新版本下的变化，并说明是否修正；
  - systemd 服务、日志、预算上限；
  - 快照保留与异地副本、恢复演练（含 `index.sqlite` 重建）；
  - 如果已有 WP-G，还包括嵌入进程的托管；
  - §2 所列快照相关遗留；
  - 观察项：启动时重建 P6 增量状态的耗时（P6 验收：100 万事件比 P4 多约 4.6 s），日常规模下明显时再优化；`/api/events` 首次加载与 `/api/usage` 的全表扫描。
- **工作量：** 2–3 天。**风险：** 低。

## 6. 已确认的决定

### 6.1 “纠正”在 V2 中的含义（负责人已确认，2026-10-21）

**决定：采用（a）。**

- **更正作为原始经历入档，可以被查阅。**
  - 具体做法：更正逐字入档；在原文窗口期间可见；离开窗口前经过一次整理；之后可以被 `check` 查到，与旧说法按时间一起返回（P4 §1）。
  - YUVI 是否相信、采纳以及如何重新理解它，由模型自己决定，作为研究观察。
- **可信边界由程序确定。**
  - 身份认证、权限、访问范围等可信边界，按 AGENTS 不变量 3、4，由程序依据来源确定；
  - 它们不属于模型可以自行重新解释的记忆事实。
- **不采用（b）。**
  - 不建立“更正必然生效”的记忆机制；
  - 以后涉及身份与权限的 P，按上一条的可信边界处理，不把它们当作记忆。
- V1 用 R4/R5 由程序维护“记忆权威”，V2 不采用这一结构（其中已验证的存取经验可以继承）。

### 6.2 记忆架构与路线（2026-10-21，原则上采用）

见 [05-decisions.md](research/memory/05-decisions.md)：

- 四类划分；
- 自由文字为当前主要载体，不排斥其他表示；
- 语义向量按需引入；
- 激活为可开关、可比较的研究机制；
- 路线采用，技术细节按选型调研修正。

仍留给负责人的事项都不阻塞 WP-A～WP-C。

## 8. 每个 P 的固定格式

- **P 文件：** 目标、范围（做 / 不做）、对外接口与约束、验收标准、交付约定，一页到两页；引入依赖时写明选型依据（AGENTS“依赖与架构选型”）。
- **验收标准在交给 Sol 前确定。** Sol 可以因真实的技术障碍提出修改，并说明原因：
  - 不涉及范围的修改，由 Claude 决定，并在 P 文件中标注日期；
  - 涉及范围或架构的修改，交给负责人决定。
- **Claude 的验收：**
  - 检出 PR 分支，独立运行 P 文件中的检查（用 Claude 自己写的脚本与假模型服务）；
  - 审阅代码是否违反 [`AGENTS.md`](../AGENTS.md) 中的不变量；
  - 在 PR 评论中记录结果：通过 / 不通过，以及不通过时对应的检查项与复现命令。
- **不在验收中提出新要求。** 发现的范围外问题，记为下一个 P 的候选。
- **合并：** 验收通过后由负责人合并。
