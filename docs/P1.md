# P1　最小对话回合：可持久的浏览器对话

> 周期 C1 的第一个工作包。实施：Sol。验收：Claude。状态：**可交付 Sol**（2026-10-21；同日补充回复发送尝试与中断结果的记录语义）。
>
> 只需读本文件和 [`AGENTS.md`](../AGENTS.md)。本文件与其他任何资料冲突时，以本文件为准。

## 1. 目标

P1 完成后，V2 第一次成为一个能用的东西：

- 一个常驻进程，在浏览器里与 YUVI 文字对话，回复流式出现；
- 每一句话（负责人的与它的）按时间写入一个只追加的 SQLite 档案；
- 进程重启后对话不丢，而且模型能看到之前的对话；
- 模型调用失败或进程中途崩溃时，系统如实记录，不伪造回复，也不伪装成沉默。

## 2. 范围

### 必须完成

1. **进程。** Node.js 22 + TypeScript，代码从仓库根目录组织。所有运行时状态都在 `YUVI_DATA_DIR` 下的一个 SQLite 文件里。
2. **档案。**
   - 一张只追加的事件表，至少包含 §3.2 列出的字段。
   - 在数据库层面拒绝对已有事件的 `UPDATE` 与 `DELETE`（例如用触发器）。
3. **一个回合：**
   1. 收到消息后，**先**写入一条 `experience/heard` 事件，再调用模型；
   2. 用人设文件和本场景最近的事件组装上下文（§3.3）；
   3. 以流式调用一个 OpenAI 兼容的 Chat Completions 接口，把增量实时推给客户端；
   4. **在把第一个增量推给客户端之前**，写入一条 `act/reply_attempt` 事件（`reply_to` 指向 `heard`，`model` 必填）。从这一刻起，回复已经开始对外发送；
   5. 完整生成后，写入一条 `act/said` 事件，内容为完整回复，`reply_to` 指向对应的 `heard`，`meta.attempt` 为 `reply_attempt` 的 `id`。
4. **失败与中断。**
   - **模型调用失败**（HTTP 错误、超时、流中断）：写一条 `control/error`（`reply_to` 指向 `heard`），客户端收到明确的错误，不写 `said`。其中 `meta.outcome` 按是否已开始发送区分：
     - 尚未写 `reply_attempt`：`"not_sent"`；
     - 已写 `reply_attempt`：`"partial"`。此时 `meta.attempt` 为该 attempt 的 `id`，`content` 为已推给客户端的文本。
   - **进程在生成中被杀死：** 重启时，对每条“没有 `said` 也没有 `error`”的 `heard`，补写一条 `control/error`（`meta.reason = "interrupted"`），其中 `meta.outcome` 按是否已开始发送区分：
     - 没有 `reply_attempt`：`"not_sent"`；
     - 有 `reply_attempt`：`"unknown"`。已发出多少、对方收到多少都不可知，不猜测，也不补写内容；`meta.attempt` 为该 attempt 的 `id`。

     不重新生成，也不补发回复。

   - P1 不需要逐块持久化增量，也不需要完整的效果账本。

5. **顺序。** 同一场景的消息按到达顺序串行处理；生成期间到达的消息排队，不丢弃，也不并发生成。
6. **网页。**
   - 进程在 `/` 提供一个最小的单页：输入框、对话列表、流式显示。
   - 打开页面时显示已有历史。
   - 不需要框架和样式工作。
7. **测试。** `npm test` 不访问外部网络和真实模型，测试中的假模型服务由 Sol 自己实现。安装依赖（`npm ci`）可以联网。
8. **说明。**
   - 在根目录 `README.md` 中补充怎样安装、启动、配置和测试；
   - 在 `docs/notes/P1.md` 中写重要的实现选择与对本文件的偏离（不超过一页）。

### 明确不做

- 记忆与回忆：记忆整理与回忆、`recall` / `check`；
- 工具与主动性：任何工具调用、沉默工具、主动开口、心意；
- 接入与身体：QQ、语音、Live2D、看图；
- 数据与研究：V1 数据导入、潜在组织；
- 运行与部署：多用户与登录、Tauri、打包、systemd 部署、备份（P3 做）、费用计（P2 做）；
- 上下文处理：上下文压缩或摘要、任何语义标注（情绪、意图、重要性）。

## 3. 接口与约束

以下是验收要用到的**对外约定**，必须照此实现；其余由 Sol 决定（§3.6）。

### 3.1 包管理与命令

- 使用 npm，提交 `package-lock.json`。
- `npm ci` 安装。
- `npm test` 运行全部测试。
- `npm start` 启动服务。
- 如需构建步骤，在 `npm start` 或 `prestart` 中自动完成。

### 3.2 配置（环境变量）

| 变量                      | 含义                                | 默认                 |
| ------------------------- | ----------------------------------- | -------------------- |
| `YUVI_DATA_DIR`           | 数据目录，SQLite 文件放在其中       | 必填                 |
| `YUVI_MODEL_BASE_URL`     | OpenAI 兼容接口的基地址（含 `/v1`） | 必填                 |
| `YUVI_MODEL_API_KEY`      | 密钥                                | 必填（假服务可任意） |
| `YUVI_MODEL`              | 模型名                              | 必填                 |
| `YUVI_PERSONA_FILE`       | 人设文本文件路径                    | 必填                 |
| `YUVI_HOST` / `YUVI_PORT` | 监听地址                            | `127.0.0.1` / `8787` |
| `YUVI_CONTEXT_EVENTS`     | 上下文中最多包含的最近事件数        | `200`                |

### 3.3 事件字段（`GET /api/events` 返回的 JSON 中必须出现）

| 字段         | 要求                                                             |
| ------------ | ---------------------------------------------------------------- |
| `seq`        | 整数，递增                                                       |
| `id`         | 字符串，唯一                                                     |
| `branch`     | P1 恒为 `"dev:v2-dev"`                                           |
| `class`      | `experience` / `act` / `inner` / `control`                       |
| `kind`       | —                                                                |
| `scene`      | P1 恒为 `"web"`                                                  |
| `actor`      | 负责人的消息为 `"owner"`；它的回复为 `"yuvi"`；错误为 `"system"` |
| `t_recorded` | 毫秒                                                             |
| `reply_to`   | —                                                                |
| `content`    | —                                                                |
| `model`      | `said` 必填                                                      |
| `meta`       | 对象                                                             |

P1 用到的 `class/kind` 组合：`experience/heard`、`act/reply_attempt`、`act/said`、`control/error`。`control/error` 用 `reply_to` 指向它所对应的 `heard`。

### 3.4 上下文

- 发给模型的请求是：一条 system 消息（人设文件的全文），加上本场景最近事件按时间排列、带作者的原文。
- 原文的具体格式由 Sol 决定，可以用 user / assistant 消息，也可以用一条带时间与作者前缀的文本。但两点必须满足：
  - 每条内容的作者与先后可以辨认；
  - 不加入任何程序生成的语义标注或 JSON 摘要。
- `reply_attempt` 与 `control/error` 不进入上下文；它们对应的未完成回复的 `heard` 要进入上下文。（把“上次回复被中断”的事实交给模型，是后续 P 的候选。）

### 3.5 HTTP 接口

| 方法与路径                    | 行为                                                                  |
| ----------------------------- | --------------------------------------------------------------------- |
| `GET /health`                 | 200，`{"ok":true}`                                                    |
| `POST /api/messages`          | 见下文                                                                |
| `GET /api/events?after=<seq>` | 返回 `seq > after` 的全部事件，按 `seq` 升序；省略 `after` 时返回全部 |
| `GET /`                       | 网页                                                                  |

`POST /api/messages`：

- 请求体 `{"text": string}`。
- 响应为 `text/event-stream`，依次发送：
  1. `event: heard`，`data` 为该事件的 `id`；
  2. 若干 `event: delta`，`data` 为 `{"text": ...}`；
  3. 最后 `event: done`（`data` 为 `said` 的 `id`）或 `event: error`（`data` 为 `{"message": ...}`）。
- 空文本或只含空白，返回 400。

### 3.6 必须遵守的边界

- **仓库：** 只修改本仓库。不依赖 V1 仓库的任何包。
- **可以参考：** V1 中 OpenAI 兼容流式传输的写法（[`openai-compatible-stream.ts`](https://github.com/Ruichen-0079/YUVI/blob/0d894cc70d42ebba0df132924f5ea181c062b431/packages/providers/src/openai-compatible-stream.ts)）。复制过来的代码归本仓库所有。
- **不修改：** `AGENTS.md`、`docs/ROADMAP.md`、`docs/P1.md`。对它们有意见，写在 PR 描述里。
- **密钥：** 不写入数据库、日志和错误信息。
- **监听：** 默认只监听 `127.0.0.1`。
- **文档：** 不新增设计文档；`docs/notes/P1.md` 以一页为限。

### 3.7 由 Sol 决定

- SQLite 驱动（`node:sqlite` 或 `better-sqlite3`）、HTTP 框架、目录与模块结构；
- 表结构中的其他字段与索引；
- 上下文的具体排版、网页实现；
- 测试框架、日志格式；
- 超时数值（须在 `docs/notes/P1.md` 写明）。

## 4. 验收标准

**执行方式。** Claude 在 Linux 上用 Node 22，使用**自己编写**的 OpenAI 兼容假模型服务和脚本执行检查，不使用 Sol 的测试替身。假服务能够：

- 按块、按设定间隔返回指定文本的流式响应；
- 返回 500；
- 在发出第一块之前挂起，或在发出若干块之后挂起；
- 在发出若干块之后断开连接；
- 记录收到的请求体。

**A3 的通过条件：**

- SSE 依次为 `heard`、若干 `delta`、`done`；
- 所有 `delta` 拼接等于“我在。”；
- `/api/events` 中按序出现 `heard`（`actor=owner`）、`reply_attempt`（`actor=yuvi`，`reply_to` 等于 `heard` 的 `id`）与 `said`（`actor=yuvi`，`reply_to` 等于 `heard` 的 `id`，`model` 非空，`meta.attempt` 等于 `reply_attempt` 的 `id`）；
- 假服务在第一块之后暂停 2 秒，期间查询 `/api/events`：客户端已收到第一个 delta 时，`reply_attempt` 已经存在，`said` 尚不存在。

**A7 的通过条件：**

- SSE 收到 `event: error`；
- 档案中有该 `heard`，以及一条 `reply_to` 指向它的 `control/error`（`meta.outcome="not_sent"`）；没有 `reply_attempt`，没有 `said`；
- 随后一条正常消息正常完成。

**A7b 的通过条件：**

- SSE 先收到两个 delta，再收到 `event: error`；
- 档案中有 `heard`、`reply_attempt`，以及一条 `control/error`：`meta.outcome="partial"`，`meta.attempt` 指向该 attempt，`content` 等于“我在想”；
- 没有 `said`。

**A8 的通过条件：**

- 重启后，该 `heard` 有一条 `reply_attempt`，以及一条 `control/error`：`meta.reason="interrupted"`，`meta.outcome="unknown"`，`meta.attempt` 指向该 attempt；
- 没有 `said`；
- 再发一句时，上下文包含那条未回复的消息；
- 不会自动重发，也不会补回复。

**A8b 的通过条件：**

- 重启后，该 `heard` 有一条 `control/error`：`meta.reason="interrupted"`，`meta.outcome="not_sent"`；
- 没有 `reply_attempt`，没有 `said`。

**完成判据：** A1–A13（含 A7b、A8b）全部通过。

**真实模型检查：** 由负责人用真实的 DeepSeek 密钥对话几句，确认能用。它不作为判据。如果它失败而全部验收项都通过，作为新问题处理，不回溯判定 P1 不通过。

- 是否违反 §3.6 或 `AGENTS.md` 的不变量；
- 是否存在明显会丢数据或伪造事件的路径；
