> V1 知识归档的一部分，总索引见 [README](README.md)。
>
> - **来源：** V1 历史债务研究（`docs/research/project-history/HISTORICAL_DEBT.md` @ `3f6a9393`，YUVI PR #338）、项目史与研究基础（同一提交）、V1 `main` @ `0d894cc7` 与未合并堆叠 @ `a1b89423` 的代码、验证记录和 CI 记录，以及本归档调查时对这些提交的直接核对。
> - **写法：** 每条教训写明 V1 发生了什么、证据在哪里、得出什么结论，以及 V2 中对应的规则。D 编号对应 `HISTORICAL_DEBT.md` 的债务条目，便于回查原文。

## 0. 总判断

V1 的主要负担不是“代码写得差”。大部分代码有测试，很多正确性边界经过真实环境验收。

负担来自四个相互强化的机制：

1. 早期宪章把“程序替模型预加工”写成永久规则（§1.1）；
2. 多代理协作的安全机制被写进了系统的概念模型（§2.1）；
3. 为尚不存在的模型、消费者与平台预建边界（§1.4、§3.2）；
4. “先地基、后研究”没有停止条件（§2.3）。

结果是：系统很擅长证明自己保存了什么、没有越权做什么，却几乎没有被要求具备“理解”的能力。

## 1. 架构与概念

### 1.1 给代理的宪章就是架构（D1）

**发生了什么：** 05-10 的 V1 `AGENTS.md` 第 4、5 条写着“Memory should never be raw chat logs dumped into prompts”“must be retrieved, ranked, compressed, and reconstructed before prompt injection”。这个文件五个月没有改动，却是每个编码代理会话必读的指令。它为 L1 摘要、Dream 整合、上下文压缩、关键词情绪等一切“先加工再给模型”的设计提供了合法性。第 12 条（生产桌面不依赖 Node/PostgreSQL）后来与 R5 发行包直接矛盾。

**证据：** V1 `AGENTS.md` @ `0d894cc7`；初始提交 `4bffc50d`。

**教训：** 写给代理的指令文件与研究命题一起演化，否则最早的临时判断会以最高权威持续存在。

**V2：** `AGENTS.md` 只写研究宗旨、协作制度、选型原则和不变量；不变量的修改要负责人同意，其余随里程碑由 Claude 维护。

### 1.2 程序替模型理解（D7）

**发生了什么：** 凡是需要判断的地方都长出了规则或分类器。

| 形式 | 证据 | 后果 |
| --- | --- | --- |
| 关键词情绪标签（8 条正则，固定置信度） | `packages/memory/src/affect.ts` @ `0d894cc7`；在 `main` 上一直生效，只在未合并的 PR #322（提交 `c1475dae`）中退役 | 实测把“我不担心这个问题”判为 anxious（0.82），错误提示到达模型 |
| “Don't forget” 被理解为删除 | V1 生产智能损失审计 F3；PR #322 修复（未合并） | 程序误解语义，造成破坏性操作 |
| 控制协议失败被合成为“成功的沉默” | 同一审计 F6 | 失败被掩盖成有意义的选择 |
| 桌面回合被预设为“在对 YUVI 说” | PR #232 | “是否被呼唤”由程序判断 |
| QQ 准入规则 + 本地小模型预过滤 | Plunge 分支提交 `9a99ae7d` | 主模型看不到被过滤的旁听 |
| 已发表文本逐条截到 800 字；`length` 整体拒绝 | PR #323（未合并）修复 | 事实在进入模型前丢失；恢复原文后 0/3 → 3/3 |
| SILENCE 不写入历史 | PR #234 | “我选择了沉默”这一经历被抹去 |
| 正则判定“重要”（`记住|重要|决定了`）和“未解决”（`吗|怎么`） | `dream-consolidation.ts`、`recent-episode.ts` @ `0d894cc7` | 程序给经历贴语义标签 |

**教训：** 程序负责可核验的关系（谁、何时、回复谁、来源、权限、是否送达），并如实标注不确定；意义交给模型。程序侧的语义判断在边缘情况会系统性出错，而且错误隐蔽。

**V2：** 写入 `AGENTS.md` 研究宗旨的第一条工程含义。P4 起的对话组装给原文，不做逐条截断、程序摘要或语义分节；P7 记录每次请求实际呈现了什么（`control/presented`）。

### 1.3 记忆的目的决定记忆的形态（D2）

**发生了什么：** V1 的记忆从 05 月起就是为“助手更了解用户”设计的：用户偏好与项目事实、按类别的 TTL、规则化的取代、日常经历默认不存（提交 `d96edbc0`）。抽取方式在 LLM 与规则之间反复切换（05-17 LLM → 09-08 规则 → R5 禁止规则回退）。A10.1a 用编造偏好的桩模型复现：LLM 抽取路径会把模型的编造写成带伪造来源、归为“用户”的核心记忆。这是测试中复现的缺陷，没有证明生产中实际发生过。

**教训：** 为个体经历设计的记忆，不能从“为助手提供用户事实”的记忆演化而来；任何派生解释都必须能指回精确原文。

**V2：** 只追加档案记录它自己的经历；它写下的文字是它自己的，不做抽取与归类（[ROADMAP](../../ROADMAP.md)、[`research/memory/03`](../../research/memory/03-architecture.md)）。

### 1.4 用规则模拟自主，或用禁令排除自主（D8）

**发生了什么：**
- **规则模拟：** 主动发言先后是 Web 计时器（空闲 12 s、冷却 30 s），然后是 Runtime 门槛 + 固定退避（NO_OP 后 30 s、发言后 120 s），最后是“说话分数 ≥ 0.7”。模型只在规则放行后做一次打分（详见 [02 §5](02-systems.md#5-主动性调度与内在活动)）。
- **禁令排除：** 09-24 的整合把北极星中的慢变量、欲望张力、人格惯性统一列为“不得建立的心理状态”。这条禁令从未被检验。

**教训：** 两条路都没有让模型基于自身经历形成倾向。“不要用化妆品式变量名假装有情绪”是对的，但它要求的是“变量必须有因果作用、可以消融”，不是“不许有变量”。禁令应改写为实验门槛。

**V2：** 研究机制作为可开关的机制，通过消融与对照检验：WP-F 的激活，以及 [ROADMAP §5](../../ROADMAP.md) 的潜在组织。变量不按人类心理学命名。

### 1.5 为模型的弱点设计，会固化弱点（D6）

**发生了什么：**
- DeepSeek V4 不能稳定输出控制前导，主动路径于是变成“70B 模型决策 + 写作模型续写”（PR #61）。
- 为一个假想的后训练 Character 模型预建了 Character ABI 2A–2D、Harness 5A–5L（PR #100–#115；#115 明说“后训练模型确定前不实现适配器”）。训练在 09-01 延期，模型从未出现，但“gate + 正文”的两次 Chat 调用一直留在生产中。

**教训：** 对模型能力不足的补偿要标注为临时措施，换模型时重新验证，不能写成架构。边界在至少有两个真实调用方后再抽象。

**V2：** `AGENTS.md`“不预先建立通用抽象”；模型通信只保留一个流式请求入口。

### 1.6 没有消费者的结构不会自己变成能力

**发生了什么：** 合同包直到 PR #283 才接入生产（“Production Character reconstructed P8/Memory semantics from prompt text”）。Profile 物化后无人读取。Dream 的 idle 触发在生产中从未发生：调用方从不传 `idleMs`，服务端也没有独立 worker。约 35 个 PR 只为把一个 soft-smile 表情接上完整的 effect 生命周期。

**证据：** V1 后端智能价值审计 F6；PR #283；`runtime-orchestrator.ts` @ `0d894cc7`。

**教训：** 结构的价值只能由消费者证明。验收要问“这个产物进入模型了吗”，而不只是“它被正确地生成了吗”。

**V2：** P7 的出发点就是记录并核对“组装了什么、发送了什么、模型实际收到了什么”。

### 1.7 大量“记忆失败”其实是上下文管道失败

**发生了什么：** 800 字截断、`length` 整体拒绝、SSE 心跳丢弃正文、mock 测试绕过 Character，都直接造成事实丢失。恢复原文后事实即恢复（PR #323 0/3 → 3/3；PR #327 修正长输入尾部）。

**教训：** 先保证原文完整进入上下文，再讨论记忆机制；测试必须经过生产装配。

**V2：** P4 的原文窗口：未整理的对话事件整条进入上下文，离开原文窗口只能经过它自己的整理，或者有记录的积压移出（`control/unconsolidated`）。P6 把它增量化，P7 记录每次请求的实际呈现。

## 2. 过程与协作

### 2.1 多代理流程变成了架构（D5）

**发生了什么：** 08-18 起，AgentBus 让浏览器端模型写规格与评审、编码代理实现与审计，PR 评论成为状态机。08-28 的路线图用“每个关注点唯一权威”的表格防止代理互相覆盖。08-29 到 09-01 按“最小原子”实现：08-31 一天创建 70 个 PR。

**后果：**
- **原子化先于消费者**（见 §1.6）。
- **治理词汇成为思维语言：** authority、admission、fail-closed、frozen、SHA-fenced、“no second Runtime/authority”。这些词适合防止代理越界，却让“一个统一的内部状态同时影响多种行为”这类研究设想显得越权。
- **审计的真实性有限：** 多条 `CODEX_AUDIT: PASS` 写明“pnpm 不可用、测试未运行”；并行代理产生重复 PR（#134/#137/#139/#145/#147）；#96 过早合并后被回滚。

**V1 已出现的自我修正：** PR #235“连续两次没有新证据就停止”；PR #260 反过度工程门槛；PR #203 先用已有上下文。

**教训：** 协作安全机制留在流程层（CI、评审），不写进系统的概念模型；模块边界由研究问题决定，不由“哪个代理负责哪段代码”决定。

**V2：** 以里程碑为委派单位、一个 PR 一份完整交付、一次集中独立验收（`AGENTS.md`“工作单位”“实施、验收与 PR”）。验收者用自己的驱动实际执行检查，报告区分实测与推断。[TERMS](../../TERMS.md) 列出不得带入的 V1 治理词汇。

### 2.2 文档权威的通胀（D11）

**发生了什么：** `docs/future/` 的 README 自称“CURRENT FUTURE AUTHORITY”，规定文档之间的权威顺序；A8.2、A10.1 都有自己的“leaf execution authority”。到堆叠顶端，`docs/` 有 679 个文件、约 48 MB，源码约 10 MB。09-24 的整合把 09-19 的北极星降为“历史资料”，此后的代理只需引用权威索引就能拒绝重新讨论被排除的想法。

**教训：** 研究文档要区分“我们相信什么、为什么”与“当前代码是什么”。前者要能被新证据推翻，不由权威顺序保护。IMPLEMENTED / PLANNED / HYPOTHESIS 这类状态标签本身是有价值的。

**V2：** 一个里程碑一份规格；研究文档写明“已验证 / 假设”；本归档用五类状态标注 V1 能力（[README](README.md#状态分类)）。

### 2.3 “先地基、后研究”没有停止条件（D9）

| 时间 | 承诺 | 实际 |
| --- | --- | --- |
| 08-28 | 先完成结构整理，再开始 P8 | 完成后进入一天 70 个 PR 的原子化 |
| 09-12 | v0.1.3 是“最后的地基版本”，之后研究记忆动力学 | 09-24 地基被重新定义为“持久因果历史” |
| 09-24 — 10-07 | A0–A12 完成后进入研究版本 | 10-10 起转入记忆权威与发行候选 |
| 10-19 | — | E1–E8 实验与长期轨迹回放设施从未建立 |

**形成机制：** 每次哲学推进都提出更严格的正确性要求（可归因、可纠正、可迁移），这些要求先被翻译成地基工程，地基工程又暴露出新的正确性缺口。

**教训：** 地基的完备度由“下一个实验需要什么”界定。研究闭环的最低条件（可靠记录 + 可纠正事实 + 可重放）在 10 月初已经具备。

**V2：** 每个里程碑写明完成判据。ROADMAP 把回忆、重整与激活（WP-E/F）排在检索与评测设施（WP-C/D）之后，并允许潜在组织的离线研究在 WP-B 之后开始（ROADMAP §5）。

**需要留意：** 研究机制排在工程之后，本身就是 V1 循环的形状。V2 的防线是 WP-C/D 有明确的范围和工作量估计，并且“不做”清单只有 Claude 或负责人可以改（`AGENTS.md`“工作单位”）。如果 WP-C/D 的实际工作量明显超过估计，应当把这一条当作信号。

### 2.4 测试证明的范围被高估（D10）

**发生了什么：**
- mock 下的测试绕过了 Character（PR #327 才修正），生产中的两次调用与上下文截断长期没有覆盖。
- 发行候选（PR #336/#337）只用了 fixture 模型，“真实模型 B”被阻断。
- 真实模型实验通常每组 3 次。
- “4,144 个测试通过”“百万向量 p95 2 ms”容易被读成“记忆有效”。
- `main` 的 Check 工作流从 `9776aca9`（10-07 快进合入）到 `0d894cc7` 连续失败，原因是 Smoke 步骤 `POST /message` 返回 `503 JOURNAL_UNAVAILABLE`（推断为 Check 任务没有 PostgreSQL 服务）。语音服务的 Python 测试不在 CI 中。

**教训：** 每个结论都回答“它证明的是基础设施成立，还是某个假说成立”。

**V2：** 测试离线、不用真实模型；验收报告区分实测、推断、未验证；研究假说留给专门的评测设施（ROADMAP WP-D）。

### 2.5 在无法证明的问题上反复加超时是无效劳动

**发生了什么：**
- PR #20（Windows 私有 PostgreSQL 的进程身份证明）：27 个提交、44 条 AgentBus 评论，卡在“如何证明某 PID 是自己启动的 PostgreSQL”，最后关闭。
- DIAG229/230（PR #226–#230）：19 个提交、MSAA/COM 自动化，只为验证托盘退出。根因（`shutdown_supervisor()` 是否返回）至今没有定论。

**教训：** 设定停止规则：连续两次没有新证据就停下，改换问题或平台（PR #235）。研究项目的第一平台是作者实际使用的平台。

**V2：** 只支持 Linux；单进程、单个 SQLite 文件，不由应用管理数据库进程。

### 2.6 历史本身的流失（D12）

**发生了什么：**
- QQ 插件的构建提交（`7dcf4b01`、`e8a09719`、`dbb4b984`）在公开仓库中不可达；
- 七月没有提交；
- 需求与取舍主要发生在与模型和代理的对话中，未入库；
- 09-14 至 10-07 的核心工程（66 个提交）在分支上开发，10-07 快进并入 `main`，没有 PR 与评审痕迹。

**教训：** 决策记录与实验记录本身就是研究资产，要与代码同等保存。

**V2：** 规格、澄清与验收结论都写在仓库或 PR 中；负责人不转发消息，问答留在 PR 评论里；本归档就是对这一条的补救。

## 3. 依赖与平台

### 3.1 外部组件的价值要在引入前写下（D3）

**发生了什么：** 08-04 引入 Mem0，仓库里没有选择理由。一周后 PR #9 关闭了普通回合的 `infer=true`，即 Mem0 的核心语义能力，剩下一个需要独立 Python 进程的向量库。

随之而来：
- PyInstaller 打包（PR #8，33 个提交）；
- 持久摄取账本、租约、幂等、对账（PR #11–#17）；
- Supervisor 所有权（PR #266/#267）；
- Linux 包中的 sidecar（PR #311）。

R5 最终用自建 PostgreSQL 记忆权威取代它，legacy、Mem0、R5 三套记忆并存。

**教训：** 引入外部组件前写下它独有的价值；能力被关闭时重新评估去留。“为一个外部进程做到崩溃安全”本身会产生大量看似必要的工作。

**V2：** `AGENTS.md`“依赖与架构选型”：选型写进 P 文件，写明许可证、维护状况与替换成本；数据不依赖第三方库的内部状态恢复。V2 的选型研究见 [`research/memory/06`](../../research/memory/06-selection.md)。

### 3.2 平台先行（D4）

**发生了什么：** 6 月 Windows-first（PR #1），8 月为 Windows 安装包做了私有 PostgreSQL、凭据管理器、NSIS、托盘。泥潭见 §2.5。08-25 转向 Linux-first（PR #54），09-05 删除 Windows CI（PR #236）。

进程所有权的严格要求被带到 Linux。未合并的 PR #337 用 systemd 用户服务 + cgroup + pidfd 解决：14 类故障矩阵在最终包上全部通过。但这类问题本身来自“由应用自管数据库进程”的选择。

**教训：** “一体化桌面安装包”是产品目标，不应先于研究闭环。如果确实要管理子进程，用操作系统的收容机制（cgroup），而不是去证明 PID 归属。

## 4. 哪些复杂性是必要的

不是所有 V1 的复杂性都是负担。以下几项对任何长期存在的人工个体都是必要的；V2 做得更简单，但没有省略：

| 必要的复杂性 | V1 中为什么需要 | V2 中的形式 |
| --- | --- | --- |
| 记录发生了什么的不可篡改日志 | 否则无法回答“我是否真的经历过”，也无法做因果消融 | 只追加档案（不变量 1） |
| 归因与来源 | A10.1a：没有来源，模型的编造会被写成用户说过的话 | 每个事件有类别、场景、作者、时间（不变量 2） |
| 纠正语义：取代但保留历史 | R4 之前，自然语言纠正产生零候选（PR #324） | 更正用新事件表达（不变量 1） |
| `UNKNOWN` 与不重放 | 否则崩溃后会对自己的行动产生虚假记忆 | 意图 → 尝试 → 结果（不变量 5） |
| 单一生命的恢复纪律 | 冷恢复时撤销旧凭据、未决动作不伪造成功（PR #336/#337） | 分支三类（不变量 7）；P3 冷备份与恢复 |
| “模型提议、系统提交”，限于外部效果、身份与世界事实 | 防止自我确认循环与身份伪造 | 不变量 3：身份、权限、删除核对来源；`inner` 不核对 |

它们的共同点是服务于“忠实地知道自己经历了什么”。V1 的债务集中在另一半：没有给模型留下理解、形成倾向和改变自己的空间。

## 5. 不应成为 V2 约束的历史偶然

以下是 V1 在特定时间、为特定原因做出的选择，不作为 V2 的前提：

- Mem0 及其 sidecar、打包与投递账本；
- Windows-first 与应用自管 PostgreSQL；
- L0/L1/L2 分层、30 分钟情节窗口、Dream 的触发规则；
- Character/Cognition 双模型分工、`NEED_COGNITION` 协议、Harness、gate + 正文两次调用；
- 主动性的具体计时常数与 `NO_OP|REQUEST_TEXT` 冻结；
- “唯一权威”表、atom 粒度、Campaign/Atom/Astra 编号；
- 09-24 的心理变量禁令；
- V1 `AGENTS.md` 中的 AIRI 定位、默认 Provider 与第 4、5、12 条；
- DeepSeek V4、GLM、Llama-70B 等具体模型选择，以及围绕它们弱点建立的结构；
- 行为规范/偏好数据集格式与 SFT/DPO 训练路线。
