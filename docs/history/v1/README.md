## 一页结论

**V1 有什么：** 一个 Linux 本地伴侣运行时，包括：

- Tauri 桌面与托盘、Supervisor、PostgreSQL + pgvector；
- 本地 STT、本地 TTS、Live2D、按需截屏；
- 用户画像式记忆（PG `memories`、Mem0、L0/L1/L2、Dream）、关键词情绪；
- Character 决策加可选 Cognition；
- 计时器驱动的主动发言；
- 后期的 Journal 接收凭证、effect 账本、多角色、QQ 适配，以及未合并的 R5 记忆权威。

**实际运行了什么：** 10 月日常运行的是 09-08 的构建（`5064c29f`，含 PR ≤ #279）。其中有：

- 桌面、语音、Live2D；
- Mem0 与 L0/L1/L2 记忆、关键词情绪、回合后的 Dream、联想侵入；
- 默认关闭的主动发言。

09-08 之后合并到 `main` 的工程（生产语义接线、gate + 流式正文、Journal、effect 账本、多角色）以及全部未合并分支，都没有进入日常使用。QQ 只在 10-07、10-08 用未合并的 Plunge 分支实机试运行过（[02 §0](02-systems.md#0-先看部署v1-实际运行的是哪个版本)）。

**哪些是好的：**

- 来源与权限工程：接收凭证、归因、`UNKNOWN` 不重放、冷恢复、密钥保管；
- 存取工程：中文词项 + 语义混合召回及其失败模式、可重建的派生索引；
- 语音服务的工程形态与 Linux 打包纪律；
- 一套好的研究理论：过去改变未来、人格惯性、时间印象、测量先于变量；
- 证据分级与“无新证据即停止”的过程纪律。

**哪些失败了：**

- 记忆的对象是用户，不是它自己；
- 程序替模型理解：关键词情绪、正则“重要性”、准入规则、截断与摘要；
- 主动性由计时器和打分代劳，内部状态被禁令排除；
- 研究机制从未运行：E1–E8、动力学、潜在状态；
- 合同先于消费者；为假想的模型与平台预建边界；
- 多代理流程的治理语言变成了系统的概念语言；
- “先地基、后研究”没有停止条件。

**为什么 V2 不直接继承：** V2 蓝图的判断是，V1 “把研究对象的性质逐一换成了易记录、易验证的显式表示”，合起来造出的是一个高度可靠的长期 Agent，而不是研究对象。所以 V2 继承的是知识与原则，不是代码、架构或生活：

- 新仓库、新个体；
- 只追加档案与它自己的记忆分开；
- 程序只处理可核验的关系。

**来源在哪里：** [05](05-sources.md) 列出所有固定基准点、文档、提交与 PR。主线二手来源是 V1 项目史研究（YUVI PR #338 @ `3f6a9393`），关键事实都经过一手核对。

## 状态分类

[02](02-systems.md) 中每项能力标注以下五类之一：

| 状态 | 含义 |
| --- | --- |
| **实际使用** | 出现在负责人实际运行的构建中，并且有实机记录。10 月的日常构建是 `5064c29f`；9 月的实机记录见 Campaign B/G/I 与 Linux 发行门 |
| **已测未部署** | 已合并到 `main`、有测试，但不在实际运行的构建中，或者没有实际使用的证据 |
| **未合并** | 只在未合并的分支上：R4/R5 堆叠（PR #322–#337）或 Plunge 分支。Plunge 曾实机试运行的，另行注明 |
| **仅设计** | 只有设计文档，没有实现 |
| **已取代** | 已被 V1 自己弃用或取代 |

## 未能核实的信息

以下事项在仓库与可读记录中没有足够证据，本归档不作断言：

1. **部署版本：** 10-11 之后日常安装是否更换过构建。R5 文档把 `5064c29f` 的日常安装称为“日常 Alice”，而 Alice 的独立人格与多角色组合是 10-07 之后才有的；Plunge 文档又称 10-07/08 从 ZIP 启动了 Alice，R5 文档 10-10 的核对却没有发现 QQ 入口在运行。这几条记录之间的关系不明。
2. **QQ 实机运行：** 所有真人 QQ 交互的结论都来自代理写的验证文档，原始请求与日志在私有目录，没有被独立复核。私聊连发导致重复回复的问题被标为“未解决”，之后如何不明。
3. **实际使用频率：** 主动发言是否被开启过，以及打扰率；声纹是否日常录入；语音模式和 Live2D 的人工验收是否完成；Dream 在真实部署中完成过多少作业。
4. **不在仓库中的证据：** 人格校准 v7–v10（PR #222）；TTS 选型 bakeoff；旧 QQ 插件的构建提交（`7dcf4b01`、`e8a09719`、`dbb4b984` 在完整克隆中不存在）。
5. **决策的归属：** 889 个提交署名同一账号，无法区分负责人、各个代理的贡献；09-24 的 13 项整合（包括心理变量禁令）是否经负责人逐项认可，没有记录。需求与取舍主要发生在未入库的对话中。
6. **样本量：** 真实模型实验大多是 n=3；gate 消融只有一个模型；主动性对比每个模型 80 次，没有预注册阈值；R5 视觉实验只有 2 张合成图；STT 延迟没有任何实测。
7. **CI：** `main` 的 Check 从 10-07 起连续失败。原因（Check 任务没有 PostgreSQL，Journal 返回 503）是从日志推断的；`main` 的分支保护设置无法读取（403）。
8. **部分统计：** Windows 相关 PR 的数量（16 个、80 个提交）是按标题和分支名关键词统计的近似值。AgentBus 中“审计写明测试未运行”的说法沿用项目史研究，本次没有重读全部评论。

## 怎样使用本归档

- **提出方案之前**，先在 [04](04-v2-inheritance.md) 与 [03](03-engineering-lessons.md) 中查是否已有结论或失败记录（`AGENTS.md`“实施、验收与 PR”）。
- **移植 V1 的算法、常数或代码时**，在规格中写明来源（path@SHA），并说明它在 V1 中的状态。“已测未部署”和“未合并”的东西没有经过日常使用。
- **不带入 V1 的词汇**（TERMS §3）。本归档使用 V1 的词，只是为了准确指称历史对象。
- **需要 V1 的真实数据时**，先由负责人批准对应的里程碑；本归档不提供也不指向任何私人内容。
- **更新本归档：** 发现新的证据或更正时，直接修改相应文件，并在文件头注明日期。不另建平行文档。
